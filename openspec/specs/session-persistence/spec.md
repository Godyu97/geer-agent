# session-persistence Specification

## Purpose

让用户能在退出后恢复同一工作目录中的对话，并继续使用压缩后的上下文。会话保存原始记录与可恢复的安全检查点；恢复时以实际保存成功的状态为准，明确中断与保存故障，避免自动重放有副作用的工具。

## Requirements

### Requirement: 可选会话存储

系统 MUST 在未配置会话数据库时继续使用内存会话；配置受支持数据库后 MUST 独立于模型调用 Trace 保存会话标识、原始消息和压缩事件，以及可直接恢复的检查点。持久化内容 MUST 不包含 API key、认证头或数据库凭据。

#### Scenario: 默认未配置

- **WHEN** 没有配置会话数据库
- **THEN** 对话和压缩可正常运行，退出后不会出现可恢复的持久化会话

#### Scenario: 配置数据库

- **WHEN** 用户配置受支持的数据库并进行对话及压缩
- **THEN** 原始记录和最新成功发布的检查点可按 Session ID 读取，压缩不删除原始记录

### Requirement: 列表与安全恢复

系统 MUST 提供 `/sessions` 显示当前 workspace 的近期会话，并提供 `/sessions --all` 显示所有 workspace 的近期存档和进程内会话；全部范围的条目 MUST 标注所属 workspace。系统 MUST 提供 `/open <session-id>` 打开进程内或已保存会话，并保留 `/resume <session-id>` 的兼容行为。恢复 MUST 验证模型、接口、服务端点、检查点格式、消息关联和会话记录的 workspace；成功后 MUST 切换至该 workspace、重新加载环境上下文、清空工具授权且不得自动重跑工具。打开当前会话 MUST 保持原状态，恢复失败 MUST 保持当前会话和授权。

#### Scenario: 恢复压缩会话

- **WHEN** 用户从另一 workspace 恢复曾经压缩并正常退出的会话
- **THEN** 系统切换到记录中的 workspace，Session ID、摘要与近期原文继续可用，后续输入沿用该会话

#### Scenario: 工具执行中断

- **WHEN** 会话在工具执行中断后恢复
- **THEN** 系统显示最近安全检查点及工具副作用未确认状态，并等待新的用户输入

#### Scenario: 不兼容或损坏的会话

- **WHEN** 目标会话的配置或格式不兼容，消息关联已损坏，或记录中的 workspace 已不存在、不是目录或不可访问
- **THEN** 系统拒绝恢复，说明原因并保留当前会话、workspace 和工具授权

#### Scenario: 打开当前会话

- **WHEN** 用户打开当前会话的 UUID
- **THEN** 当前历史、待保存内容、workspace 和授权均保持不变

#### Scenario: 当前目录列表

- **WHEN** 用户执行 `/sessions`
- **THEN** 系统合并显示当前 workspace 的进程内会话和近期存档，并按 UUID 去重

#### Scenario: 全部目录列表

- **WHEN** 用户执行 `/sessions --all` 或在 GUI 选择全部范围
- **THEN** 系统合并显示所有 workspace 的近期存档和进程内会话，并为每条记录显示所属目录

### Requirement: 会话独立保存 Workspace

系统 MUST 让每条进程内及持久化会话独立保存规范化的 workspace。关闭会话持久化时，进程内会话仍 MUST 在切换和往返打开时恢复自己的目录；保存失败时，原会话的 workspace 和待补写内容 MUST 留在该会话中供后续重试。

#### Scenario: 内存会话跨目录往返

- **WHEN** 会话持久化关闭，用户在 workspace A 对话、切换至 B，再打开 A 的进程内会话
- **THEN** 系统恢复 A 的目录和历史，B 的历史仍隔离保存

#### Scenario: 保存失败后切换

- **WHEN** workspace A 的会话保存失败后用户切换至 B
- **THEN** 系统允许切换，并在后续保存时继续补写 A 的原事件、检查点和 workspace

### Requirement: 保存失败与重置

会话保存失败时系统 MUST 警告并继续本次对话，后续保存 MUST 尝试补写未保存增量；退出后恢复结果 MUST 只承诺最后一次成功保存的检查点。`/reset` MUST 建立新会话并清空授权，不删除已保存的旧会话。

#### Scenario: 写入失败后补写

- **WHEN** 一次保存失败、后续数据库恢复可用
- **THEN** 系统告警后继续，在后续检查点补写，并使成功发布的记录可恢复

#### Scenario: 重置后恢复旧会话

- **WHEN** 用户重置后通过旧 Session ID 恢复
- **THEN** 旧历史重新可用，工具授权需再次确认

### Requirement: 派生会话展示标题

系统 MUST 以第一条实际用户消息生成会话展示标题，合并空白、去除控制字符后取前 20 个 Unicode 字符，超长追加省略号，无用户消息时显示“新会话”。标题 MUST 仅用于展示，不单独持久化，不改变 UUID 唯一标识。压缩与恢复 MUST 保留原始首条输入的标题；历史读取失败 MUST 回退显示短 UUID 并给出诊断。

#### Scenario: 压缩后重启

- **WHEN** 用户保存包含多轮消息和压缩历史的会话并重启程序
- **THEN** 列表仍显示原始首条输入的标题，UUID 不变，打开后的上下文正常恢复

#### Scenario: 同名与空会话

- **WHEN** 两条会话首条输入相同，另有一条空会话
- **THEN** 同名会话仍按不同 UUID 区分，空会话显示“新会话”，各条目的完整 UUID 均可查看

### Requirement: 单条与批量删除会话

系统 MUST 支持按完整 UUID 删除一条或多条进程内及持久化会话，删除快照和消息事件，保留 Trace。重复 ID MUST 去重，目标已不存在 MUST 支持安全重试。批量操作 MUST 逐项报告成功、已不存在、失败或残留消息清理告警；单项失败 MUST 不阻止其他项。删除 MUST 不要求原 workspace 或模型配置仍可用于恢复。

#### Scenario: 删除后保存和重启

- **WHEN** 用户删除包含未保存内容的历史会话，随后保存全部会话并重启
- **THEN** 删除目标不会重新出现在列表或恢复成功，其 Trace 仍可读取，其他会话保持不变

#### Scenario: 部分失败与重试

- **WHEN** 批量删除中部分会话失败或消息清理失败
- **THEN** 系统逐项显示原因并提供重试目标，不把残留清理错误报告为完全清理成功

#### Scenario: 旧检查点并发保存

- **WHEN** 另一个进程试图用已删除会话的旧版本保存
- **THEN** 保存失败且不能重新创建该会话的可恢复检查点

### Requirement: 删除当前会话

当前会话删除成功或确认已不存在时，系统 MUST 在原 workspace 创建新的空 UUID 会话，清空旧消息区、输入草稿、本轮用量及工具授权。删除失败 MUST 保留当前会话；删除其他会话 MUST 保持当前状态。已删除目标 MUST 不再参与后续保存。

#### Scenario: 当前会话包含在批量目标中

- **WHEN** 当前会话与多条历史会话一同被成功删除
- **THEN** 系统只创建一个新的空会话，沿用原 workspace，旧会话不会被保存流程重新写入

### Requirement: 删除命令与确认

系统 MUST 提供 `/delete <id> [id...]` 和显式 `--yes` 参数。交互界面无 --yes 时 MUST 先确认并默认取消；非交互输入无 --yes 时 MUST 只提示用法，不读取后续输入作为确认。确认 MUST 显示目标数量与完整 UUID、保留 Trace 的说明，以及当前会话替换提示。

#### Scenario: 管道安全输入

- **WHEN** 管道依次输入不带 --yes 的删除命令和另一条命令
- **THEN** 删除不执行，后一条命令按原语义处理

#### Scenario: 显式批量删除

- **WHEN** 用户输入 `/delete --yes` 后跟多个完整 UUID
- **THEN** 系统删除精确指定的目标并逐项输出结果，不接受标题、前缀或通配符代替 UUID
