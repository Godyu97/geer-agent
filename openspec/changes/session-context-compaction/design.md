# Design

## Context

见 proposal.md。当前 `Prompt` 拥有 Chat/Responses 历史及 pending；`agent` 在每次模型步骤前获取快照，`provider` 无会话状态。`TraceStore` 已有 SQL 与 MongoDB 连接，Trace 记录包含 Session ID，但它不是可恢复的会话状态。现有模型用量是单次用户请求的累计指标，不能直接代表下一次请求的上下文大小。

## Goals / Non-Goals

**Goals:** 保持 Prompt 的消息所有权和两种协议的完整负载，在用户轮次和工具循环中安全压缩，并把会话恢复到最近成功保存的状态。普通 `cargo run` 继续可用。

**Non-Goals:** 跨协议转换、分支会话、自动重放中断工具与跨设备同步。

## Decisions

### Prompt 投影与边界

`Prompt` 持有会话的有效消息、前次摘要、当前轮次及未保存原始事件；持久化快照不含可重新生成的 system 环境提示。Chat 与 Responses 继续保存各自的 SDK 消息，统一的是轮次边界和检查点格式，不将 Responses 的输出粗暴转为纯文本。`messages()` 只投影 system、历史摘要与有效原文；历史摘要作为有明确标记的用户层背景消息，避免将旧工具文本提升为 system 指令。每次模型调用和对应的整个工具批次视为不可拆分单元，当前用户输入固定保留。`rollback_turn` 仅撤销本轮待提交输入，不回滚此前成功的压缩。

教程按最近六条消息切割容易截断工具配对，因此按约 20,000 tokens 倒序选择完整单元。单轮过大时只在已完成工具批次间切分；单条当前输入过大则明确报错。每次只摘要旧摘要及新切出的前缀，保留的近期原文不再重复摘要。

### 预算与摘要请求

`CompactionConfig` 默认窗口 272,000、触发比例 0.9、近期预算 20,000、摘要输出预算 4,096。`GEER_AGENT_CONTEXT_WINDOW_TOKENS` 与 `GEER_AGENT_AUTO_COMPACT` 提供用户配置；小窗口按比例缩减保留与摘要预算。估算器读取即将发送的完整 `Messages` 和工具说明，按序列化 UTF-8 体积与消息开销给出保守估值；已有普通请求的 input usage 用来校准下一次估计。它是触发器，不声称精确 token 数。

`agent` 在普通请求前、工具批次结束后检查；可用时调用现有 `ChatProvider` 发起无工具的摘要请求。请求使用同一模型和服务端点，保留 Trace 捕获、超时及错误语义；不向 REPL 流式显示摘要正文。为 Chat/Responses 建立明确的完整文本与完成状态读取，拒绝截断、空白和工具调用。大前缀按完整单元分块摘要，每块成功且估算量缩小时才替换对应前缀；已成功块保持有效，失败块仍保留原文。发生明确上下文溢出且未输出正文时，最多进行一次压缩重试。失败时记录该前缀在本次用户请求已尝试，避免循环。

摘要请求的实际用量进入本次资源上限与费用估算；单独统计维护调用，不当作普通 Agent Turn。开始前检查剩余时长和资源预算；用量缺失时沿用现有严格预算语义。普通回答的 streaming 与回调接口保持原样。所有异步模型调用只持有从 Prompt 生成的只读消息快照，完成后才可变借用 Prompt 提交摘要，避免跨 `.await` 持有两份可变历史。

### 会话存储与安全恢复

`SessionStore` 是与 `TraceStore` 并列的业务接口，共用 SQL/MongoDB 连接与迁移基础，不从 Trace 记录重建对话。会话头保存 ID、工作目录、协议、模型、去除凭据的端点标识、更新时间、revision、最近原始事件 ID 和带版本的 Prompt 快照。原始事件以 UUID、父事件 ID、类型、脱敏负载追加保存，涵盖输入、完整模型输出/工具结果、摘要和回滚。保存先幂等写入事件，再以 revision 条件发布头；读者沿已发布的父链读取事件，忽略写入失败遗留的孤儿记录。SQL 使用固定名称的新迁移，保留旧 Trace 迁移身份；MongoDB 使用独立集合与索引，不要求跨文档事务。

数据库不可用或写入失败时告警并继续，内存保留待写事件；下次检查点补写，故障期间不能承诺恢复到最新内存状态。冲突 revision 不覆盖另一写入者，当前进程继续内存对话并报告尚未保存。会话恢复先验证完整快照和消息配对，再一次性交换当前 Prompt/Session；恢复后重新生成 system 上下文并清空工具授权。工具批次执行中只恢复到最近完整检查点，向用户提示可能存在未确认副作用，不自动重放。

配置沿用现有环境变量与启动校验方式。会话数据库两项变量缺一时报错；未配置时不连接数据库。端点仅保存不含认证信息的稳定标识；已知 API key、认证头、数据库 URL 在原始事件与快照持久化前脱敏。会话数据属于用户隐私，不写入仓库文件。

### REPL 与文档

`/compact` 复用自动压缩核心；`/sessions` 列出当前工作目录近期 20 个会话；`/resume <id>` 先完成全部校验再切换，失败保留当前会话。`/reset` 新建 Session ID 而不删除旧存储。帮助与 README 说明配置、失效范围和安全检查点。摘要进度作为状态信息显示，不进入对话历史。

## Risks / Trade-offs

- [估算偏离兼容模型的真实 tokenizer] → 使用真实 usage 校准及一次明确溢出恢复；公开窗口可配置。
- [摘要遗失细节] → 先保真结构化摘要、保留近期原文；持久化原始事件便于审计，首版不提供跨会话检索。
- [进程在工具执行中退出] → 仅发布完整批次的消息检查点，恢复提示未确认副作用且不重跑。
- [持久化部分成功或并发恢复] → 事件唯一 ID、条件 revision 和已发布头隔离孤儿写入。
- [数据库连接或写入故障] → 继续内存会话并明确最后成功的恢复点。

## Migration Plan

先实现内存压缩，再扩展可选会话存储与 REPL 命令。新 SQL 表/索引由独立迁移创建；现有 Trace 表和已应用迁移不改名。未启用会话存储的现有启动方式无需数据迁移，回滚代码时新表可保留而不会影响 Trace。
