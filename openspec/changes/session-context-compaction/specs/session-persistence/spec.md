# Spec Delta

## Purpose

让用户能在退出后恢复同一工作目录中的对话，并继续使用压缩后的上下文。会话保存原始记录与可恢复的安全检查点；恢复时以实际保存成功的状态为准，明确中断与保存故障，避免自动重放有副作用的工具。

## ADDED Requirements

### Requirement: 可选会话存储

系统 MUST 在未配置会话数据库时继续使用内存会话；配置受支持数据库后 MUST 独立于模型调用 Trace 保存会话标识、原始消息和压缩事件，以及可直接恢复的检查点。持久化内容 MUST 不包含 API key、认证头或数据库凭据。

#### Scenario: 默认未配置

- **WHEN** 没有配置会话数据库
- **THEN** 对话和压缩可正常运行，退出后不会出现可恢复的持久化会话

#### Scenario: 配置数据库

- **WHEN** 用户配置受支持的数据库并进行对话及压缩
- **THEN** 原始记录和最新成功发布的检查点可按 Session ID 读取，压缩不删除原始记录

### Requirement: 列表与安全恢复

系统 MUST 提供 `/sessions` 显示当前工作目录的近期会话，并提供 `/resume <session-id>` 恢复已保存的安全检查点。恢复 MUST 验证工作目录、模型、接口、服务端点和检查点格式；成功后 MUST 重新加载环境上下文、清空工具授权且不得自动重跑工具。

#### Scenario: 恢复压缩会话

- **WHEN** 用户在相同配置下恢复曾经压缩并正常退出的会话
- **THEN** Session ID、摘要与近期原文继续可用，后续输入沿用该会话

#### Scenario: 工具执行中断

- **WHEN** 会话在工具执行中断后恢复
- **THEN** 系统显示最近安全检查点及工具副作用未确认状态，并等待新的用户输入

#### Scenario: 不兼容或损坏的会话

- **WHEN** 目标会话的环境或格式不兼容，或消息关联已损坏
- **THEN** 系统拒绝恢复，说明原因并保留当前会话

### Requirement: 保存失败与重置

会话保存失败时系统 MUST 警告并继续本次对话，后续保存 MUST 尝试补写未保存增量；退出后恢复结果 MUST 只承诺最后一次成功保存的检查点。`/reset` MUST 建立新会话并清空授权，不删除已保存的旧会话。

#### Scenario: 写入失败后补写

- **WHEN** 一次保存失败、后续数据库恢复可用
- **THEN** 系统告警后继续，在后续检查点补写，并使成功发布的记录可恢复

#### Scenario: 重置后恢复旧会话

- **WHEN** 用户重置后通过旧 Session ID 恢复
- **THEN** 旧历史重新可用，工具授权需再次确认
