# Spec Delta

## Purpose

让长对话及连续工具调用在模型上下文窗口内继续进行，同时保留近期原文和重要旧事实。用户可以手动压缩，也可以让系统在接近预算时自动压缩；压缩失败必须可见，且不得破坏工具调用与结果的关联。

## ADDED Requirements

### Requirement: 按上下文预算自动压缩

系统 MUST 默认以 272,000 tokens 为窗口，在估算请求上下文达到 90% 时，于下一次普通模型请求前压缩可压缩的旧历史；估算 MUST 覆盖系统上下文、工具说明、摘要、消息与当前输入，并允许覆盖窗口或关闭自动触发。

#### Scenario: 新输入超过阈值

- **WHEN** 新输入使下一次请求的估算上下文达到默认窗口的 90%，且存在可压缩的旧历史
- **THEN** 系统先生成摘要，再以摘要及近期原文向模型请求回答，并显示压缩进度

#### Scenario: 工具结果超过阈值

- **WHEN** 一批工具结果进入对话后使下一次模型请求达到阈值
- **THEN** 系统在下一次模型请求前压缩，而不重复执行该批工具

### Requirement: 手动压缩与保真边界

系统 MUST 提供 `/compact`，将旧历史总结为摘要，并始终保留正在处理的用户输入；自动压缩还 MUST 优先保留近期消息原文。工具调用及其结果 MUST 成组保留或成组摘要，已生成的摘要 MUST 参与下一次压缩。

#### Scenario: 手动压缩

- **WHEN** 用户输入 `/compact` 且存在可压缩的旧历史
- **THEN** 系统显示本次压缩结果，下一次普通回答使用摘要与近期原文

#### Scenario: 历史不足

- **WHEN** 用户输入 `/compact` 但没有可压缩的旧历史
- **THEN** 系统说明未发生压缩，原历史保持不变

#### Scenario: 手动压缩唯一完整轮次

- **WHEN** 仅有一个已完成轮次且用户输入 `/compact`
- **THEN** 系统可将该完整轮次摘要，不留下不成对的工具消息

#### Scenario: 两种模型接口中的工具配对

- **WHEN** 对话包含多个工具调用、结果以及非文本模型输出
- **THEN** 压缩边界不留下孤立结果，保留的输出仍能按原协议继续对话

### Requirement: 压缩失败与超长输入

系统 MUST 仅在收到完整、非空、无工具调用且使上下文缩小的摘要后替换对应旧前缀；分块失败时 MUST 保留该块原文并显示原因，已成功提交的分块保持有效。同一失败请求 MUST 不反复压缩同一前缀；单条当前输入过长且无法安全缩短时 MUST 明确报错。

#### Scenario: 摘要失败

- **WHEN** 摘要调用超时、返回空文本、被截断或请求工具
- **THEN** 历史不被替换，用户看到告警，可在有剩余窗口时继续普通请求

#### Scenario: 模型报告上下文溢出

- **WHEN** 一次普通模型请求在未输出正文、未执行新工具时明确报告上下文溢出
- **THEN** 系统最多压缩并重试该请求一次，已执行的旧工具结果不重放
