# Proposal

## Why

GUI/Web 把模型运行状态用于禁用大部分控件，连草稿编辑、会话范围和勾选也不可用；运行中打开记忆面板后，关闭按钮与 Escape 又被禁用，造成实际无法返回聊天的体验。流式正文更新还会重复渲染历史 Markdown，长对话放大了卡顿。

## What Changes

- 思考和生成期间仍可编辑下一条草稿、筛选与选择已有会话、阅读历史、复制代码、查看和关闭记忆面板；发送及改变当前会话的操作继续等待本轮结束。
- 在输入区持续显示等待回复、接收回复、工具调用或待授权状态，解释暂不可用的操作；草稿不会自动发送，也不会被迟到的提交确认清空。
- 提供返回最新消息入口，向上阅读时不被增量输出拉回；减少长历史和连续输出对点击、输入的影响。
- 沿用 Catppuccin Mocha，统一按钮尺寸、焦点、选中态、留白和输入区层级，兼顾桌面与窄屏。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `gui`：补充图形界面运行中的本地交互、草稿保护、进度与阅读行为；桌面与 Web 共用该交互要求。

## Impact

主要修改共用 React 前端及其组件测试、模块事实与 README。保留 Rust 工作线程的串行会话所有权、事件协议、两个宿主适配及已有授权/删除安全边界。不新增依赖，不改配置或持久化格式。

## Non-goals

不增加并发会话、消息队列、停止模型/工具执行能力，不展示模型内部推理，不重做 TUI/REPL，不替换主题或引入 UI 框架。本切片聚焦运行期间仍可操作的对话界面。
