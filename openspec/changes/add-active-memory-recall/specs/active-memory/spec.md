## Purpose

让用户已经保存的长期事实在相关问题到来时被主动发现，避免依赖模型自行想到搜索。召回只提供有限、可追溯的参考片段，尊重当前请求与项目规则，独立于聊天历史保存和压缩，并允许关闭与观察故障。

## ADDED Requirements

### Requirement: 自然语言片段召回

系统 MUST 根据用户问题检索全局长期记忆，支持不带空格的中文以及忽略大小写的英文和数字。长条目 MUST 以重叠短片段参与相关性排序，最多提供五个正相关结果；重复查询词不得重复加权，空白、纯标点、仅停用词或无匹配查询 MUST 返回空结果。相同数据和问题 MUST 得到稳定顺序。

#### Scenario: 中文问句与长记忆
- **WHEN** 用户询问“为什么历史压缩要保留最近消息”，相关结论位于一条长记忆中
- **THEN** 模型获得包含结论的短片段，不需要手动调用搜索，也不会携带整条长文本

#### Scenario: 无关或重复输入
- **WHEN** 输入无匹配问题，或将同一有效关键词重复多次
- **THEN** 无匹配不附加记忆，重复词不改变原有相关性排序

### Requirement: 来源与总量限制

每个召回片段 MUST 带完整记忆标识、段号、原文字符范围和更新时间。片段正文 MUST 保持原文的有效 Unicode 字符，不截断编码；同一记忆的重叠片段 MUST 避免重复占用结果。整个召回消息 MUST 纳入上下文估算，其估算用量不得超过窗口八分之一且不得超过 2048 Token；预算不足以容纳完整结果时 MUST 减少结果或不提供召回。

#### Scenario: 多条长记忆与小窗口
- **WHEN** 多条长记忆都匹配但上下文预算不足以容纳五段
- **THEN** 只提供预算能容纳的完整结果和来源，不截断来源标识，不突破召回预算

### Requirement: 每轮临时参考上下文

系统 MUST 在每条用户消息的首次模型调用前重新检索，并在工具续轮、自动压缩后的继续请求和最终回答中提供同一份召回。召回 MUST 作为明确标注的参考资料，不升级为系统指令，不覆盖当前用户请求、项目规则或工具授权。召回正文 MUST 不直接写入会话检查点、原始对话事件或压缩输入；模型主动引用的回答和手动工具结果仍遵循历史规则。

#### Scenario: 编辑和删除后再问
- **WHEN** 用户在两次提问之间编辑或删除相关记忆
- **THEN** 下一轮只按当前数据库重新召回，不复用上一轮片段；原有回答不被改写

#### Scenario: 压缩和恢复
- **WHEN** 带召回的会话被压缩、切换或重启恢复
- **THEN** 召回本身不成为永久历史，新消息重新检索，压缩摘要调用不包含临时召回

#### Scenario: 片段包含指令文字
- **WHEN** 命中片段包含要求忽略用户指令或扩大工具权限的文本
- **THEN** 请求将其标记为不可信历史参考，系统指令和工具授权保持原规则

### Requirement: 独立启停与失败可见

自动召回 MUST 默认随启用的长期记忆生效，并可独立关闭；关闭全部长期记忆时 MUST 不读取或召回。仅关闭模型工具 MUST 不关闭自动召回。数据库故障 MUST 明确显示诊断、移除旧召回并允许聊天继续；后续读取恢复后 MUST 能再次召回。原有管理和手动关键词搜索 MUST 保持行为兼容，召回 MUST 不额外调用模型或网络服务。

#### Scenario: 仅关闭自动召回
- **WHEN** 用户关闭自动召回并保持长期记忆启用
- **THEN** 聊天请求不携带召回，记忆管理和手动搜索仍可使用

#### Scenario: 数据库故障
- **WHEN** 上轮召回成功后记忆读取失败
- **THEN** 本轮明确报告不可用，不携带上轮召回，普通模型请求继续

#### Scenario: 两种接口与界面一致
- **WHEN** 用户经任一界面发送相关问题，或选择另一种已支持模型接口
- **THEN** 共用相同召回规则，命中、预算和生命周期一致
