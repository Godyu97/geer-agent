# Design

## Context

动机与范围见 proposal。基线 `607d8ea`：`MemoryService` 通过 `Rc` 供 Agent、Tools 与 UI 共用；DAO 支持四种数据库，只缓存可用状态。`search_entries` 和前端使用相同的十条关键词规则。`Agent::handle_message` 每轮读取列表仅刷新状态；`Prompt` 已把系统指令、历史、摘要和可序列化检查点分开。

本变更跨 memory、Prompt 和 Agent，且涉及历史污染和上下文预算，因此需要设计。调研证据及完整对比落在 `docs/design/memory-retrieval.md`；不修改尚未归档的 `add-project-memory` 产物。

## Goals / Non-Goals

采用现有全局记忆库作为唯一事实来源，增加一个可测试的读取路径；模型接口、UI 写操作、存储模式保持原结构。自动召回与明确关键词的管理搜索服务不同用途，不偷偷改变已有搜索契约。本轮不建设第二个存储系统。

## Decisions

### 1. 无依赖的检索核心

新增独立 `retrieval` 模块，仅接受借用的原文，返回带来源下标、段号、Unicode 字符范围的借用片段和分数。窗口为 320 个 Unicode scalar value，重叠 80；保留原文，不用 UTF-8 字节直接截断。分块参数由调用方传入，后续 RAG 可用 800/80，不预建索引平台。

跟随教程的 BM25-lite：中文连续文本拆相邻双字，单字保留，英文和数字按词转小写；移除少量中英文停用词，查询词去重。查询最多取前 4096 字符、64 个不同有效词，以限制自然问句的评分成本。每个片段对每个词统计非重叠子串频次，一次计算文档频率和平均字符长度，再用 k1=1.2、b=0.75 评分，避免教程逐个结果反复扫描整个语料。保留子串匹配便于中文单字与代码标识片段；因此明确称 BM25-lite，不宣称语义检索或词典分词。

同分按输入来源顺序、片段序号稳定排序；memory 在检索前按创建时间、UUID 稳定排列。选取结果时跳过同一条目的相交字符范围，避免重叠块重复占预算；最多五段。完整正文和 CRUD 不变。

不选向量检索：目前小型记忆库没有新增服务、embedding 模型或索引同步的收益证据。无新增 crate，标准库与现有 JSON 序列化足够。

### 2. 一轮一份、可追溯且有预算

`MemoryService::recall` 重新读取 DAO，获取最新状态并返回可选召回文本；片段携带 UUID、1 起始段号、0 起始半开字符范围及更新时间。结果按 JSON 数据编码，内容中的换行、引号和伪分隔符不改变消息结构；不将检索分数冒充事实置信度。

预算使用现有保守的字节/2 Token 估算：以序列化后的用户消息字节数除以二向上取整，再加 12 消息开销。整份结果不超过 `min(context_window_tokens / 8, 2048)`；按排名尝试加入完整结果，放不下则略过，不做会损坏来源或语义的半段裁切。预算小到一段也放不下时返回空。没有全局硬相关度阈值，因为不同语料的 BM25 分数不可直接比较。

### 3. 独立的临时 Prompt 字段

Agent 在 begin_turn 后设置本轮召回。Prompt 对两种 API 都将其作为独立的 user-role 参考消息提供，位于历史前，当前问题仍保留原角色与位置。系统提示解释记忆可能过期、属于全局范围、不能授予权限；片段正文不会进入 system/instructions。沿用项目把摘要标记为参考资料的做法，而非照搬教程的系统提示拼接。

临时字段不进入 `PromptSnapshot`、RawEvent 或压缩原文，但进入完整上下文估算；普通请求、工具续轮、最终收敛和压缩后的恢复调用统一从 messages 组装。begin_turn、restore、reset、替换 workspace 系统提示时清空旧召回。压缩只处理真实历史，不处理本轮召回；模型回答或手动搜索工具自行带出的事实仍可能在历史中，这是既有行为。Trace 仍可记录实际请求中的参考消息，清空记忆不宣称清除历史或 Trace。

### 4. 配置、所有权与错误处理

增加 `GEER_AGENT_MEMORY_RECALL=on|off`，默认 on；`GEER_AGENT_MEMORY=off` 是总开关，关闭工具不影响自动读取。独立关闭召回时保留现有每轮记忆状态刷新。配置使用现有 on/off 校验，非法值明确退出。

仍在单线程异步运行时顺序读取数据库，不增加后台线程、额外模型请求或流式事件。查询片段借用本轮拥有的列表，仅最终少量结果转成拥有的 String 交给 Prompt；跨 await 不保留 RefCell 借用。读取错误沿用状态更新与 diagnostic，返回无召回并继续聊天；即使上轮不可用，下轮也尝试真实读取以支持恢复。

## Risks / Trade-offs

- [字面检索不能识别同义词，通用词可能误召回] → 小停用词表、五段上限、预算与当前问题优先；保留手动搜索。测试固定中英文样本，后续由真实漏召回证据决定是否引入向量。
- [跨 workspace 的全局事实可能不适用] → 明示全局且可能过期，保留来源与更新时间；后续作用域迁移单独规划，本次不猜旧数据归属。
- [指令注入] → 明确资料角色、序列化边界、固定系统规则及既有授权。提示词不能保证模型永不误用，不能宣称彻底防注入。
- [大库逐轮扫描成本] → 复用既有每轮列表读取，只计算一次语料统计，限制查询维度；面向当前学习规模。持久索引等实际数据量增长后再考虑。
- [估算不是模型精确 tokenizer] → 与现有上下文门禁一致，保守预算并单测序列化后的上限。

## Migration Plan

无需数据迁移或新增依赖；现有记忆直接参与召回。设 `GEER_AGENT_MEMORY_RECALL=off` 可退回原本的按需读取行为。通过纯检索/Prompt 单测与两种 API 的本机模拟服务验证，再顺序执行受限 `make check`。
