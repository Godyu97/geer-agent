# Proposal

## Why

现有长期记忆能保存和管理，但每轮只刷新数据库状态，模型忘记调用搜索工具时无法使用已保存的信息；中文自然问句也不适合现有空白拆词搜索。先交付教程 Day13 对应的 `active-memory` 切片，以有预算、有来源的自动召回补齐读取链路，并为 Day14 `knowledge-rag` 留下可复用的检索算法。

## What Changes

- 每条用户消息前按问题自动召回最多五段相关长期记忆，支持中文自然问句、英文和数字。
- 仅提供命中的短片段，附完整记忆标识、段落位置和更新时间；总量随上下文窗口受限。
- 召回作为本轮参考资料，两种模型接口及所有共用 Agent 的界面行为一致；工具续轮保持同一份召回，下一条消息重新检索。
- 召回不进入持久化会话上下文或压缩原文；记忆编辑、删除后下轮读取最新数据库，失败有诊断且聊天继续。
- 可单独关闭自动召回，同时保留记忆管理和手动搜索；原有关键词管理搜索、工具搜索、全局存储语义保持兼容。

## Capabilities

### New Capabilities

- `active-memory`: 自然语言问题驱动的分块检索、受限自动召回及其本轮生命周期。

### Modified Capabilities

无。已检查主 spec；`project-memory` 仍在已完成的 `add-project-memory` change 中，本次不修改其 CRUD、关键词搜索和授权契约。新增行为扩展其“按需回忆”范围，不将全部记忆自动注入。

## Non-goals

本次不增加文档采集、知识库 UI、向量数据库、embedding API、后台记忆提取或记忆整理 Agent；不改变现有全局记忆的作用域、不重写压缩和持久化。Day14 的采集、更新、删除及证据引用作为后续独立切片，在调研文档给出设计方向。

## Impact

增量修改 memory、Prompt、Agent 和配置，添加纯 Rust 检索逻辑，无新增 crate 或数据库迁移。补充中文调研与架构说明、双 API 模拟请求和隔离测试；模型网络调用次数不增加。
