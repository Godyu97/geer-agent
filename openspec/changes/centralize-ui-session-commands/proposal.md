# Proposal

## Why

文本 REPL、TUI 和 GUI 各自实现了一遍会话命令与消息执行分派，业务调用和展示混在同一段代码中。将共用执行流程收敛后，文本界面可以整体归入 UI，三种界面复用同一份 Agent 功能入口，后续会话能力也不必分别维护。

## What Changes

- 普通运行与三种界面的选择方式保持不变，文本提示、命令别名、流式输出、错误反馈与退出保存保持现有行为。
- 会话切换、压缩、保存与删除继续遵循现有语义；无确认的非交互删除不读取下一条输入。
- 工具首次授权、拒绝与会话切换撤销授权保持原有交互。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本变更是内部架构重构，使用 `skip_specs: true`；复用现有 `repl-chat`、`tui`、`gui`、`session-persistence` 与工具行为契约。

## Non-goals

- 不调整模型与工具循环、历史格式、数据库默认值、授权范围或资源额度。
- 不实现结构化模型流事件、全局事件总线或新框架。
- 不增加命令、配置、crate，或在界面间统一不同的布局和确认形式。

## Impact

在现有 `interaction` 中增加共用命令执行入口与结果类型；三种 UI 调用该入口，Agent 继续实现会话操作。文本界面从顶层迁入 `ui/repl`，终端工具授权 I/O 随之进入 UI，启动组合负责注入确认。更新模块声明、相关测试、架构文档与过时的模块边界说明。
