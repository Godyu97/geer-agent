# Spec Delta

## Purpose

让对话中的模型可以提出结构化工具请求，由本地程序执行并将真实结果送回模型，再继续生成回答。此能力为后续命令和文件工具提供统一的调用节奏，同时让无工具的普通流式聊天继续正常工作。

## ADDED Requirements

### Requirement: 工具调用循环

系统 MUST 在两种已支持的模型接口中声明可用工具，收集完整调用后执行，并使用对应调用标识回传结果；模型再次请求工具时 MUST 继续循环，直到产生最终回答或达到五轮工具调用上限。

#### Scenario: 查询当前时间

- **WHEN** 模型请求 `get_current_time`
- **THEN** 系统返回真实本地时间，模型可依据结果继续回答

#### Scenario: 多个或连续调用

- **WHEN** 模型一次返回多个调用，或收到工具结果后再次请求调用
- **THEN** 系统按顺序执行、逐一配对结果，并继续向模型请求

#### Scenario: 调用达到上限

- **WHEN** 同一用户输入已完成五轮工具调用而模型仍未给出最终回答
- **THEN** 系统停止继续调用并明确提示用户

### Requirement: 工具错误与会话历史

系统 MUST 将未知工具、无效参数和执行失败作为可读结果交给模型，且 MUST 保留已执行调用与对应结果的有效历史；未执行任何工具的模型请求失败 MUST 沿用原有回滚行为。

#### Scenario: 参数错误

- **WHEN** 模型提供无效的工具参数
- **THEN** 系统不执行该工具，返回错误结果供模型修正

#### Scenario: 工具之后的模型请求失败

- **WHEN** 工具已执行并回传结果，但后续模型请求失败
- **THEN** 系统显示失败，保留已执行的调用及结果，允许下一次输入继续

### Requirement: 工具启停

系统 MUST 允许启动时关闭所有模型工具；关闭时 MUST 不声明也不执行工具，仍可进行普通对话。

#### Scenario: 关闭工具

- **WHEN** 用户将 `GEER_AGENT_TOOLS` 设为 `off`
- **THEN** 后续模型请求不包含工具定义，REPL 继续处理普通聊天
