# Spec Delta

## Purpose

为交互终端提供可持续查看的对话、输入和用量界面，让用户在模型流式回答和工具执行期间仍能看到当前会话、上下文占用与 token 用量，并能安全完成授权及退出。

## ADDED Requirements

### Requirement: 交互界面与终端兼容

系统 MUST 在标准输入和输出均为交互终端时显示全屏对话界面，持续展示消息与输入区域；空间足够时 MUST 在消息区域旁固定展示状态面板，窄终端 MUST 优先保留消息和输入。非交互输入或输出 MUST 继续使用文本 REPL。

#### Scenario: 宽终端对话

- **WHEN** 用户在宽交互终端启动并收到流式回答或工具进度
- **THEN** 消息区持续追加对应内容，状态面板仍可见，输入区不会被输出覆盖

#### Scenario: 窄终端与窗口调整

- **WHEN** 用户将终端缩小到不足以同时显示消息和面板
- **THEN** 系统隐藏面板并保留可用的消息与输入区域；再次放大后恢复面板

#### Scenario: 管道输入

- **WHEN** 输入或输出不是交互终端
- **THEN** 系统继续使用原有文本 REPL 处理输入与输出

### Requirement: 界面内输入与授权

系统 MUST 在界面内处理普通输入、已有会话命令和工具授权确认；未经明确同意的工具调用 MUST 保持拒绝。消息区 MUST 支持查看较早内容，流式输出 MUST 连续呈现为可读正文。

#### Scenario: 会话命令

- **WHEN** 用户在界面内执行 `/help`、`/new`、`/sessions`、`/open` 或 `/compact`
- **THEN** 原命令语义保持有效，结果显示在消息区，当前会话及上下文状态随之更新

#### Scenario: 拒绝工具授权

- **WHEN** 工具请求授权且用户在界面内输入 `n` 或直接回车
- **THEN** 界面记录选择，工具不执行，模型获得拒绝结果并继续按原流程处理

#### Scenario: 滚动历史

- **WHEN** 消息超过可见区域且用户向上滚动
- **THEN** 用户可查看较早消息，并可返回最新输出

### Requirement: 用量与上下文呈现

系统 MUST 显示当前模型、会话、估算的上下文 token 数及窗口占比、本轮和本进程累计的 token 用量。流式期间的临时估算 MUST 与接口返回的真实用量明确区分；接口未报告用量时 MUST 显示不完整状态，不得将估算标成真实计费。

#### Scenario: 流式回答后获得用量

- **WHEN** 模型正在流式回答并在请求结束时报告 token 用量
- **THEN** 面板在回答过程中显示临时估算，在请求完成后更新为接口报告的本轮及累计用量

#### Scenario: 用量缺失

- **WHEN** 兼容接口没有报告某次请求的 token 用量
- **THEN** 面板标明累计用量不完整，且不以字符估算替代真实用量记录

#### Scenario: 压缩上下文

- **WHEN** 用户执行成功的上下文压缩
- **THEN** 面板按压缩后的历史更新上下文估算和占比，压缩请求报告的用量计入累计值

### Requirement: 退出并恢复终端

系统 MUST 在用户通过 `/exit`、Ctrl+C 或 Ctrl+D 退出时补写待保存会话，并恢复进入全屏界面前的终端状态；界面错误退出时也 MUST 尝试恢复终端。

#### Scenario: 正常退出

- **WHEN** 用户在交互界面输入 `/exit`
- **THEN** 系统完成原有会话补写，离开全屏界面并恢复原终端内容和输入状态

#### Scenario: 终端输入结束

- **WHEN** 用户按 Ctrl+C 或 Ctrl+D
- **THEN** 系统按退出流程保存会话并恢复终端
