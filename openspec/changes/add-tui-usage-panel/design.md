# Design

## Context

见 `proposal.md`。现有 `repl::Session` 抽象已承载会话命令与流式文本回调，`agent::Agent` 实现它；实现时将此契约和命令解析原样移至中立的 `interaction` 模块，供各界面共用。模型步骤已经返回真实用量，`Prompt` 已提供上下文估算。工具授权当前由 `Tools` 的同步确认回调直接读标准输入，交互 TUI 接管终端后必须替换该回调。现有结构化运行记录写往 stderr。

## Goals / Non-Goals

**Goals:** 复用现有 Agent 与命令语义，在 `src/ui/tui/` 实现界面和输入事件；由 `src/ui/mod.rs` 统一组合 Agent 与 TUI，`main.rs` 只启动 UI；将状态读取与授权接入点保持狭窄；交互终端默认可见，非交互场景沿用原入口。

**Non-Goals:** 不在界面层重做模型循环、工具调度或历史压缩；不把估算用量用于预算判断；不持久化 TUI 显示状态。

## Decisions

1. **界面库**：采用 Ratatui 0.30.2 与 Crossterm 0.29。标准库没有跨平台的终端备用屏幕、键盘事件、宽字符布局和增量绘制；Ratatui 是活跃的 Rust TUI 库，Crossterm 是其默认终端后端。两者版本配套，不引入额外编辑器或异步事件库。教程的 `HStack`/`VStack`、`ScrollView`、`Input` 分别映射为 Ratatui 布局、消息渲染/滚动状态和界面内的单行输入状态。相比手写 ANSI 控制序列，库承担终端恢复和跨平台显示细节。
2. **启动、边界和所有权**：`agent` 暴露构建完成的会话对象，`src/ui/mod.rs` 是唯一组合点：检查输入/输出是否为 TTY，交互路径默认创建 `src/ui/tui/` 的 TUI 并向 Agent 安装它提供的确认回调，其他场景调用原 `repl::run`。`main.rs` 只调用 `ui::run`。TUI 与 Agent 均依赖 `interaction::Session` 这一中立契约，互不引用；其他 UI 可通过同一接口在 `ui` 中接入。界面对象持有终端与消息状态，确认回调只持有可克隆的共享界面句柄；在模型回调和同步授权回调中短暂借用它。退出和错误通过守卫恢复原终端。相比由 Agent 内部启动具体界面，这个组合点避免业务层绑定 TUI。
3. **事件与异步**：空闲时读取按键和调整窗口事件；提交消息后沿用现有 async 模型循环，流式回调更新消息并立即重绘。工具确认在模型循环暂停执行工具前进入界面内的 `[y/N]` 输入状态，同步读取按键，只接受明确的 `y`/`yes`。由于当前运行时为单线程，回调没有跨线程共享需求；执行模型请求时暂不接受新的聊天提交。错误用 `Result` 返回，终端恢复不依赖成功路径。`interaction::Session` 不接收任何 Ratatui 或 Crossterm 类型。
4. **状态与用量**：为 `interaction::Session` 加只读状态与界面无关的用量回调，`Agent` 从当前 `Prompt`、模型与配置窗口读取上下文信息。每次模型请求完成就向界面报告该请求的真实输入输出 token，工具确认前也能刷新；自动压缩请求同样报告，手动压缩在命令完成后刷新状态。Agent 同时累加本轮/本进程用量，原有 `AgentMetrics` 继续用于运行预算与诊断。流式文本在界面层按字符数给临时估算并加 `~` 标记，请求结束后以真实用量替换；缺用量时标记“部分缺失”。上下文占比仅是估算，直接使用项目当前的上下文估算函数，避免与压缩阈值采用两套公式。
5. **输出与命令**：将既有输入解析及帮助文本移至 `interaction`，原文本 REPL 与 TUI 共用语义；TUI 只负责把命令结果、模型增量和工具进度显示为不同颜色的消息。现有 stderr 诊断在全屏期间暂存，恢复终端后输出，避免直接写入备用屏幕破坏布局。消息显示不解析 Markdown，也不把模型输出当终端控制序列执行。

## Risks / Trade-offs

- [模型调用期间阻塞新的按键处理] → 保持当前 REPL 的单请求节奏；流式回调仍即时刷新，授权确认在调用点处理。
- [字符估算与模型 tokenizer 不一致] → 面板明确标注估算，预算继续只用接口报告的真实用量。
- [过窄窗口无法显示完整面板或长输入] → 优先保留输入及消息，隐藏面板并对输入做水平视口。
- [底层终端或绘制失败] → 守卫在返回及 panic 时尝试恢复原始终端；错误返回给调用方。

## Migration Plan

无需数据迁移。更新依赖后 `cargo run` 经 `ui::run` 在 TTY 使用 TUI；管道场景仍运行原 REPL。移除此变更可退回原 REPL，不影响已保存的会话。
