# Proposal

## Why

现有 REPL 将回答、工具进度和命令输出连续打印到终端，用户无法在长回答中持续看到本轮用量与上下文占用。参考 GeekAgent Day 7，为交互终端增加轻量 TUI，使这些信息在对话时始终可见。

## What Changes

- 在交互终端启动时显示全屏界面：左侧可滚动的对话和工具消息、底部输入、宽终端右侧固定的模型/会话/用量面板；窄终端保留消息与输入。
- 保持原有聊天、工具授权和会话命令的操作语义；授权问题在界面内回答，拒绝仍不执行工具。
- 面板显示上下文估算及窗口占比、本轮和本进程累计 token 用量。流式回复期间显示临时估算，模型报告实际用量后更新；未报告用量时明确标示估算或缺失。
- `/exit`、Ctrl+C、Ctrl+D 后保存待写会话并恢复终端。非交互输入/输出继续使用现有文本 REPL，避免破坏管道用法。

## Capabilities

### New Capabilities

- `tui`: 交互终端布局、输入/确认、滚动、用量呈现及终端恢复。

### Modified Capabilities

无。

## Impact

对应教程 Day 7，能力 id 为 `tui`。新增 `src/ui/` 统一组装入口及 `src/ui/tui/` 实现，`main.rs` 只启动 UI；把既有会话接口与命令解析移到中立的 `src/interaction/`，TUI 不引用 `agent`，`agent` 也不引用 UI。为现有会话与工具暴露必要的状态/确认接口；增加 Ratatui 与 Crossterm 依赖。现有模型协议、工具执行规则和持久化格式不变。

## Non-goals

- 不增加 Markdown 渲染、鼠标操作、多行编辑器或新的会话数据库字段。
- 不更改工具权限策略，也不把 token 估算当成真实计费或资源预算依据。
