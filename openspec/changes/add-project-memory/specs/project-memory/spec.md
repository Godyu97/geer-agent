## Purpose

让 Agent 在新会话和恢复会话中使用当前项目的完整规则，并让用户偏好、项目事实和重要决定独立于聊天历史长期保存。用户可以在各界面直接查看和整理全局记忆，模型仅在按需搜索后读取相关条目，故障与删除范围始终可见。

## ADDED Requirements

### Requirement: 根项目指令与更新

系统 MUST 只使用当前 workspace 根目录的项目指令文档，不合并父目录、子目录或用户目录规则。启动、切换 workspace、打开会话及每条用户消息前 MUST 重新读取，普通请求、工具续轮和最终回答 MUST 携带全文；同一用户消息的工具循环 MUST 使用同一份指令。项目指令 MUST 不进入会话快照或压缩内容，并计入上下文用量。

#### Scenario: 下一条消息生效
- **WHEN** 用户修改当前根项目指令后发送新消息
- **THEN** 两种模型接口均使用修改后的全文，当前工具循环中的修改到下一条用户消息才生效

#### Scenario: 切换和恢复
- **WHEN** 用户切换 workspace 或打开属于另一 workspace 的会话
- **THEN** 系统使用目标根项目指令，恢复聊天历史不能带回旧规则

#### Scenario: 缺失与读取失败
- **WHEN** 根项目指令缺失或为空，或者读取发生其他错误
- **THEN** 缺失与空内容显示无指令，其他错误明确报告并拒绝对应启动、请求或切换，运行中原状态保持不变

### Requirement: 全局独立持久化记忆

系统 MUST 在同一数据库中独立保存全局长期记忆，跨会话、workspace 与重启共享；记忆 MUST 不随会话删除或重置而删除。存储成功前 MUST 不报告成功，失败 MUST 不回退成临时记忆。

#### Scenario: 跨项目重启
- **WHEN** 用户保存记忆，切换 workspace、新建会话并重启
- **THEN** 同一数据库中的记忆仍能查看和搜索，聊天历史与记忆独立保存

### Requirement: 添加与编辑记忆

系统 MUST 接受去除首尾空白后的非空正文，为新记忆分配完整 UUID 和创建、更新时间。重复添加 MUST 返回已有条目且不增加数量；编辑 MUST 保持 UUID 和创建时间，编辑成另一条已有正文 MUST 报冲突；不存在的编辑目标 MUST 报错而不重新添加。

#### Scenario: 重复与编辑
- **WHEN** 用户重复添加同一正文后编辑其内容
- **THEN** 只有一条记忆，编辑后的正文立即可搜索，UUID 不变

### Requirement: 按关键词搜索

搜索 MUST 按空白拆词、不区分大小写并按子串匹配。命中任意词的条目 MUST 按命中词数降序排列，同分按创建时间及 UUID 升序，最多返回十条；无结果 MUST 与执行失败明确区分。

#### Scenario: 中文与多词
- **WHEN** 搜索包含中文及多个关键词，其中条目分别命中两个、一个或零个词
- **THEN** 命中两个词的条目优先，零命中的条目不返回，界面与模型工具使用相同规则

### Requirement: 模型记忆工具

系统 MUST 向启用工具且记忆可用的模型提供保存和搜索工具，并自动执行有效调用。记忆工具 MUST 按顺序执行并遵循既有预算与结果配对约束；系统 MUST 提示保存值得跨会话保留的信息，并在需要回忆时搜索，不将全部记忆自动加入上下文。用户直接查看记忆 MUST 不向模型发送正文。

#### Scenario: 同批次写入和搜索
- **WHEN** 模型依次请求保存一条记忆和搜索相关关键词
- **THEN** 写入成功后搜索可以找到该条目，调用结果按顺序回传，不出现授权确认

### Requirement: 四种界面的完整管理

REPL、TUI、GUI 与 Web MUST 提供查看、关键词搜索、添加、编辑、单条删除和清空全部记忆。界面 MUST 显示项目指令是否加载、记忆可用状态和真实总数。TUI MUST 提供 F4 管理入口和可发现的键盘提示；图形界面 MUST 在窄屏仍可操作，操作和取消 MUST 保留聊天草稿。

#### Scenario: 手动管理
- **WHEN** 用户在任一种界面添加、搜索、编辑及删除条目
- **THEN** 列表和总数刷新，所有操作不触发模型请求，聊天草稿和会话保持不变

### Requirement: 删除与清空确认

单条删除 MUST 使用完整 UUID，清空 MUST 只删除全部长期记忆并明确全局范围与总数，不删除会话、Trace 或当前历史中已出现的文本。交互确认 MUST 默认取消；非交互输入无显式 --yes 时 MUST 不执行且不读取后续命令作为确认。已不存在的删除目标和空库清空 MUST 可安全重试。

#### Scenario: 全局清空后重启
- **WHEN** 用户确认清空全部记忆后搜索并重启
- **THEN** 总数为零且搜索无结果，已有会话、Trace 和项目指令仍可用

#### Scenario: 管道输入
- **WHEN** 非交互输入依次提交未确认的清空命令和另一条命令
- **THEN** 清空不执行，后一条命令按自身语义处理

### Requirement: 图形多端同步与过期确认

GUI 和 Web 的记忆提交 MUST 沿用串行与忙碌限制，操作后 Web 各端 MUST 同步最新列表和总数。删除与清空预览 MUST 只在发起端展示，并绑定目标及状态版本；后续操作或断线 MUST 使旧确认失效。

#### Scenario: 另一端修改后确认
- **WHEN** 一端预览清空，另一端随后添加记忆，前一端提交旧确认
- **THEN** 旧确认被拒绝，需要重新预览，新增记忆不会被过期确认删除

### Requirement: 独立启停与故障可见性

长期记忆 MUST 默认启用并可独立关闭，不依赖会话保存或 Trace 开关。关闭或初始化失败时 MUST 不声明记忆工具，并显示真实状态而不伪装为空库；聊天仍可继续。关闭模型工具 MUST 不阻止用户通过 UI 管理已启用的记忆。

#### Scenario: 关闭会话保存
- **WHEN** 用户关闭会话保存与 Trace，但记忆保持启用
- **THEN** 记忆仍跨重启保留，模型与 UI 可以使用

#### Scenario: 故障和工具关闭
- **WHEN** 记忆数据库初始化失败，或用户关闭模型工具
- **THEN** 初始化失败明确显示不可用；仅关闭模型工具时 UI 仍可管理记忆
