## ADDED Requirements

### Requirement: SQL 检查点原子发布

SQL 会话存储 MUST 将一次保存的消息增量和检查点作为一个原子结果发布；任何事件冲突、检查点冲突或写入失败 MUST 不留下该次保存新写入的消息。相同 ID 且内容一致的事件 MUST 允许安全重试，内容不一致 MUST 失败且保留原记录。

#### Scenario: 旧 revision 的保存失败

- **WHEN** 一次保存包含新的消息增量，但检查点版本已经被其他保存推进
- **THEN** 保存报告冲突，原检查点保持不变，该次新增消息不会残留

#### Scenario: 事件重试与冲突

- **WHEN** 保存遇到已经存在的事件 ID
- **THEN** 内容相同可继续发布检查点，内容不同则整次保存失败，不保留此前插入的其他增量

### Requirement: 磁盘恢复保留轮次及估算状态

系统 MUST 恢复最后成功检查点的未完成轮次和上下文估算校正，打开会话本身不得将进行中的轮次标为完成，也不得自动执行工具。缺少估算校正的旧记录 MUST 以零校正兼容恢复；格式不合法 MUST 失败且保留当前会话。

#### Scenario: 工具执行前中断

- **WHEN** 已保存的会话包含未完成轮次且工具副作用未确认
- **THEN** 恢复后保持未完成状态和原估算校正，提示副作用未确认并等待用户输入

#### Scenario: 旧检查点

- **WHEN** 用户打开没有估算校正字段的历史检查点
- **THEN** 历史与轮次正常恢复，初始校正为零
