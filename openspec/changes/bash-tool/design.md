# Design

## Context

`tool-loop` 已将模型调用交给共享工具执行入口；REPL 目前长期持有标准输入锁，授权提示需要在每轮读取后释放它。

## Goals / Non-Goals

**Goals:** 将 Bash 作为一项独立工具注册，保留已有时间工具和两种协议的调用循环。

**Non-Goals:** 不实现容器沙箱、长期权限规则或后台进程管理。

## Decisions

- 工具执行入口保存按工具名的会话授权；REPL 提供同步确认回调，首次调用展示完整命令及“授权本会话后续该工具调用”的提示。缺少可交互终端时默认拒绝，`/reset` 清空授权。后续 `read/write/edit` 复用这条授权路径，不在模型循环中写权限分支。
- REPL 仅在读取一行时借用标准输入锁，调用模型时让确认回调重新借用输入；避免两个读取者竞争。确认仅认 `y/yes`。工具开关继续由已有配置管理。
- 命令使用现有 `tokio` 的 process/io-util 功能异步启动 Bash，在启动目录运行，限制 10 秒并在超时后终止进程；流式读取标准输出和错误输出时只保留有界文本，避免先收集无限输出再截断。结果文本包含状态和截断说明。标准库缺少异步子进程/读取与当前运行时的超时组合，扩展现有 tokio features 即可，不增新 crate。
- 教程的可替换确认函数映射为 Rust 的回调和工具持有的授权集合；命令字符串按模型参数传给 Bash，不自行解析 shell 语法。仅首次授权不是命令沙箱，提示必须清楚说明授权覆盖本会话内后续 Bash 调用。

## Risks / Trade-offs

- [授权后的命令可能访问仓库外路径] → 首次提示明确说明范围；用户可 `/reset` 或退出撤销。
- [shell 子进程可能派生进程] → 超时终止直接子进程；复杂进程树隔离留给后续权限能力。
