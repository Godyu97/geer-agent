# Proposal

## Why

当前程序只在运行目录存在 `.env` 时读取配置。把二进制复制到其他目录后，用户仍需同时携带配置文件，无法按单文件方式启动。

## What Changes

- 增加可选的构建模式，将构建时的 `.env` 配置作为运行时默认值随二进制携带。
- 该模式下，进程环境变量优先于运行目录的 `.env`，运行目录的 `.env` 优先于内嵌配置。
- 未启用该模式时，现有配置读取行为保持不变；启用时若构建目录没有 `.env`，构建明确失败。

## Capabilities

### Modified Capabilities

- `repl-chat`：扩展 OpenAI 兼容配置的来源与优先级。

## Non-goals

- 不加密内嵌配置，也不增加运行时配置编辑功能。
- 不改变模型请求、REPL 或 API 选择行为。

## Impact

- Cargo feature、`config` 模块与构建运行说明。
- 启用该模式的产物会包含 `.env` 中的密钥，分发对象需要由用户控制。
