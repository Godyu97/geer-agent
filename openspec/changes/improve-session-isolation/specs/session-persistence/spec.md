# Spec Delta

## ADDED Requirements

### Requirement: 进程内独立会话

系统 MUST 在一个进程内保留多条以 UUID 标识的会话；切换后每条会话 MUST 保持自己的原始历史、摘要和待保存内容，模型请求及调用记录 MUST 仅关联当前会话。真正切换时 MUST 清空工具授权；打开当前会话 MUST 保持原状态。

#### Scenario: 两条会话往返

- **WHEN** 用户在会话 A 对话及压缩，使用 `/new` 创建会话 B 并对话，再用 `/open <session-id>` 切回 A
- **THEN** A 继续使用自己的历史和摘要，B 的消息不进入 A 的模型请求，B 仍可再次打开

#### Scenario: 未启用会话持久化

- **WHEN** 用户关闭会话持久化，在同一进程中创建并切换两条会话
- **THEN** 两条会话仍可分别继续，退出后不承诺恢复

#### Scenario: 授权隔离

- **WHEN** 用户在 A 授权工具后切至 B，再切回 A
- **THEN** 两次真正切换均清空工具授权，后续工具使用需要重新确认

#### Scenario: 打开当前会话

- **WHEN** 用户打开当前会话的 UUID
- **THEN** 当前历史、待保存内容和授权均保持不变

## MODIFIED Requirements

### Requirement: 可选会话存储

系统 MUST 在未配置数据库时默认将会话标识、原始消息、压缩事件和可恢复检查点写入当前工作目录的 SQLite 数据库；用户 MUST 能单独关闭会话持久化并继续使用内存会话。持久化内容 MUST 不包含 API key、认证头或数据库凭据。

#### Scenario: 默认未配置

- **WHEN** 用户没有配置数据库并进行对话
- **THEN** 会话写入当前工作目录的默认 SQLite 数据库，退出后可按 Session ID 恢复

#### Scenario: 配置数据库

- **WHEN** 用户配置受支持的数据库并进行对话及压缩
- **THEN** 原始记录和最新成功发布的检查点可按 Session ID 读取，压缩不删除原始记录

#### Scenario: 关闭会话持久化

- **WHEN** 用户关闭会话持久化
- **THEN** 对话和压缩继续运行，不因会话功能写入数据库

### Requirement: 列表与安全恢复

系统 MUST 提供 `/sessions` 显示当前工作目录的近期存档与进程内会话、当前标识和保存状态；提供 `/open <session-id>` 打开进程内会话或恢复已保存的安全检查点，并保留 `/resume <session-id>` 的兼容行为。恢复 MUST 验证工作目录、模型、接口、服务端点和检查点格式；成功后 MUST 重新加载环境上下文、清空工具授权且不得自动重跑工具。失败打开 MUST 保持当前会话和授权。

#### Scenario: 恢复压缩会话

- **WHEN** 用户在相同配置下恢复曾经压缩并正常退出的会话
- **THEN** Session ID、摘要与近期原文继续可用，后续输入沿用该会话

#### Scenario: 工具执行中断

- **WHEN** 会话在工具执行中断后恢复
- **THEN** 系统显示最近安全检查点及工具副作用未确认状态，并等待新的用户输入

#### Scenario: 不兼容或损坏的会话

- **WHEN** 目标会话的环境或格式不兼容，或消息关联已损坏
- **THEN** 系统拒绝恢复，说明原因并保留当前会话

#### Scenario: 合并列表

- **WHEN** 近期存档包含本进程的一条会话
- **THEN** `/sessions` 仅显示一次该 UUID，并能区分当前会话及待保存或冲突状态

### Requirement: 保存失败与重置

会话保存失败时系统 MUST 警告并继续本次对话，保留失败会话的待写内容以供后续补写；退出后恢复结果 MUST 只承诺最后一次成功保存的检查点。`/new` 与 `/reset` MUST 建立新会话并清空授权，不删除或遗忘进程内旧会话。`/save`、正常退出及输入结束时 MUST 尝试补写所有待保存会话，并明确报告仍未保存的 Session ID。revision 冲突 MUST 不覆盖其他写入者。

#### Scenario: 写入失败后补写

- **WHEN** 一次保存失败、用户切至另一会话、后续数据库恢复可用
- **THEN** 原会话的未保存内容仍在，后续保存补写并使成功发布的记录可恢复

#### Scenario: 重置后恢复旧会话

- **WHEN** 用户重置后通过旧 Session ID 恢复
- **THEN** 旧历史重新可用，工具授权需再次确认

#### Scenario: 并发 revision 冲突

- **WHEN** 另一进程先更新同一 Session ID，当前进程随后保存
- **THEN** 当前进程显示冲突并保留本地内容，不覆盖已发布的检查点

#### Scenario: 退出仍未保存

- **WHEN** 某条会话在正常退出前仍无法保存
- **THEN** 程序显示该会话 UUID，并仅承诺此前成功发布的检查点
