# Design

## Context

见 proposal.md。当前 Responses 的 `ModelStep.text` 为空，正文位于 `output` 的消息内容中；`Prompt::transcript()` 只读原始事件的 `text`，所以完成快照和恢复历史会丢失正文。GUI 桥接把模型增量和核心发出的整段工具进度标记一起发送为 `delta`。前端按单条历史分页并逐条渲染工具。

## Goals / Non-Goals

局限于展示投影、GUI 桥接和前端。不修改 Provider 请求、模型上下文、数据库格式或工具授权；不新增 crate 或 npm 依赖。

## Decisions

1. 在展示投影读取正文：优先使用非空 `text`，否则读取 `output` 中助手消息的公开文本（含可显示拒绝内容）。只遍历白名单消息及内容类型，不暴露推理或工具参数。选择展示层修复可以直接修复已存会话；只填充新请求的 `ModelStep.text` 无法解决历史数据。
2. Rust 通过借用原始 JSON 提取字符串，再将展示文本拥有为 `String`，不移动或修改模型上下文。缺字段使用 `Option` 跳过，保持既有错误/回滚记录。教程的历史展示在此映射为原始事件的只读投影。
3. GUI 桥接识别核心以完整回调发出的固定工具进度标记，发送携带请求 id 的 `tool_progress` 事件；不扫描正文内部的相似文字。不改异步 Session 接口或终端输出。前端继续丢弃过期请求事件。
4. 按用户消息边界构建展示轮次，整轮分页。同轮工具归并为单个原生 `details/summary` 区块，默认关闭，正文按原顺序展示在外；工具区块放在首次工具位置。展开时渲染详情并限制详情滚动高度。会话 id 与轮次起点组成稳定 key，避免下一轮更新影响已有折叠状态。
5. 活跃轮次单独累积正文和工具进度，完成快照取代临时状态。授权弹窗和错误提示保持原有显示路径。
6. 称呼仅属于 GUI 展示。配置仍沿用现有 `.env`，不添加主题配置。CSS 使用 [Catppuccin 官方色板](https://github.com/catppuccin/catppuccin#-palette) 的 Mocha 变量，统一背景、正文、蓝色用户标识、紫色助手标识、警告和按钮；输入区增加可见用户身份。

## Risks / Trade-offs

- 核心工具进度标记改变 → 用独立 Rust 回归测试固定桥接分类，并保留普通增量原文。
- 一轮包含大量工具 → 默认不挂载展开内容，展开区域内部滚动；整轮分页确保调用不会拆散。
- 流式文本与完成快照的结构不同 → 用界面测试覆盖流式、工具进度、完成替换、旧请求丢弃与切换。
- 浏览器验证不能替代 WebKitGTK/WebView2 真机验收 → 分别记录前端交互、Rust 编译和平台验证边界。

## Migration Plan

构建前端后编译 GUI。无需数据库迁移；恢复原始记录时自动读取现有正文。回退代码不会改写存储数据。
