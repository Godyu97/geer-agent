# Spec Delta

## Purpose

桌面 GUI 让用户在窗口中读取连续、完整的模型回答，区分自己的消息和助手正文，并按需查看同一轮提问产生的工具调用详情。统一称呼和配色帮助用户快速辨认界面状态，避免工具信息淹没对话内容。

## ADDED Requirements

### Requirement: GUI 正文在完成和恢复后保留

窗口 MUST 在流式回答结束后保留可显示的模型正文，且恢复已有会话时显示原始记录中的正文。工具调用前后的助手说明 MUST 保持可见且不重复；内部推理和工具参数不得被误作助手正文。

#### Scenario: Responses 回答完成
- **WHEN** 模型通过 Responses 接口返回正文并完成本轮回答
- **THEN** 正文在流式阶段和回答完成后均可见，不被空白历史覆盖

#### Scenario: 恢复已有正文和工具记录
- **WHEN** 用户打开已保存的会话，其中包含助手回答及工具调用前的说明
- **THEN** 窗口还原这些正文，工具结果作为独立详情显示

### Requirement: GUI 按轮折叠工具调用

窗口 MUST 将一次用户提问到下次提问之间的全部工具调用信息汇集为一个默认折叠、可展开的区块，显示调用数量；执行期间的工具进度也 MUST 进入折叠区块。助手正文、错误反馈及授权询问 MUST 保持独立可见。无工具的轮次不得生成空区块。

#### Scenario: 多次调用穿插回答
- **WHEN** 同一轮中多个工具调用与助手说明交替出现
- **THEN** 窗口仅展示一个工具汇总区块，展开可依次查看全部工具详情，助手说明与最终回答仍在区块外

#### Scenario: 历史加载与会话切换
- **WHEN** 用户加载更早记录或切换到另一会话
- **THEN** 工具只归属于对应提问，不跨轮或跨会话混合，分页不会拆开一轮工具记录

#### Scenario: 流式阶段与完成阶段
- **WHEN** 工具调用不断增加并最终生成回答
- **THEN** 汇总数量随进度更新，完成后详情替换为已记录的工具结果，正文中不出现工具进度刷屏

### Requirement: GUI 称呼与 Catppuccin 配色

窗口 MUST 使用「李火旺🔥」标识用户消息及输入身份，使用「Geer」标识助手消息及输入提示，整体采用 Catppuccin Mocha 配色，并保持正文、工具详情、禁用状态及警告可辨认。

#### Scenario: 桌面对话界面
- **WHEN** 用户查看历史、输入消息或等待助手回答
- **THEN** 对应角色显示指定称呼，背景、面板、正文和强调色统一使用 Mocha 色板
