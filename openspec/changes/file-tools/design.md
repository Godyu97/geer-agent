# Design

## Context

共享工具入口已有时间和 Bash 工具、会话授权及两种协议的调用循环。文件操作只需扩展工具清单和执行函数，不改模型循环。

## Goals / Non-Goals

**Goals:** 用 Rust 标准库完成文本读取、写入与精确替换，保持 pi 的核心参数语义。

**Non-Goals:** 不引入图片处理、模糊匹配、插件式文件操作或新 crate。

## Decisions

- 注册 `read(path, offset?, limit?)`、`write(path, content)` 和 `edit(path, edits[])`。模型参数用现有 JSON 依赖校验；相对路径基于启动时工作目录，绝对路径原样使用，`~/` 展开到用户家目录。授权按工具名独立保存，与 Bash 一样由 REPL 首次确认。
- `read` 只接受有效 UTF-8，行号从 1 开始；每次最多返回 2000 行/50 KiB，带下一起始行提示。遇到单行超出字节上限时明确报错并建议 Bash；按字节限制后再做 UTF-8 边界检查，避免切出无效字符。
- `write` 用标准库创建父目录并写入完整文本。`edit` 先读原文件，在原内容上检查每个非空旧文本唯一、各匹配区间互不重叠，再一次生成新内容并写回；匹配失败不做任何修改。保留 UTF-8 BOM 和原有 CRLF/LF 换行，避免一次小修改造成全文件无关差异。标准库足够完成这些操作，不加文件处理 crate。
- 三个工具返回简短字符串结果，错误作为工具结果让模型修正。工具调用循环只持有工具执行入口的可变借用，不需重写异步流式处理；已有 `GEER_AGENT_TOOLS` 配置统一关闭所有工具。

## Risks / Trade-offs

- [会话授权覆盖任意本机路径] → 首次提示写明范围，`/reset` 撤销；这是用户选定的访问模型。
- [文件在读取和写入之间被外部修改] → 本次按学习项目的单次顺序执行处理，不加入跨进程锁。
