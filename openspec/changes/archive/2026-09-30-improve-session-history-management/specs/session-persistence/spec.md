# Spec Delta

## ADDED Requirements

### Requirement: 派生会话展示标题

系统 MUST 以第一条实际用户消息生成会话展示标题，合并空白、去除控制字符后取前 20 个 Unicode 字符，超长追加省略号，无用户消息时显示“新会话”。标题 MUST 仅用于展示，不单独持久化，不改变 UUID 唯一标识。压缩与恢复 MUST 保留原始首条输入的标题；历史读取失败 MUST 回退显示短 UUID 并给出诊断。

#### Scenario: 压缩后重启
- **WHEN** 用户保存包含多轮消息和压缩历史的会话并重启程序
- **THEN** 列表仍显示原始首条输入的标题，UUID 不变，打开后的上下文正常恢复

#### Scenario: 同名与空会话
- **WHEN** 两条会话首条输入相同，另有一条空会话
- **THEN** 同名会话仍按不同 UUID 区分，空会话显示“新会话”，各条目的完整 UUID 均可查看

### Requirement: 单条与批量删除会话

系统 MUST 支持按完整 UUID 删除一条或多条进程内及持久化会话，删除快照和消息事件，保留 Trace。重复 ID MUST 去重，目标已不存在 MUST 支持安全重试。批量操作 MUST 逐项报告成功、已不存在、失败或残留消息清理告警；单项失败 MUST 不阻止其他项。删除 MUST 不要求原 workspace 或模型配置仍可用于恢复。

#### Scenario: 删除后保存和重启
- **WHEN** 用户删除包含未保存内容的历史会话，随后保存全部会话并重启
- **THEN** 删除目标不会重新出现在列表或恢复成功，其 Trace 仍可读取，其他会话保持不变

#### Scenario: 部分失败与重试
- **WHEN** 批量删除中部分会话失败或消息清理失败
- **THEN** 系统逐项显示原因并提供重试目标，不把残留清理错误报告为完全清理成功

#### Scenario: 旧检查点并发保存
- **WHEN** 另一个进程试图用已删除会话的旧版本保存
- **THEN** 保存失败且不能重新创建该会话的可恢复检查点

### Requirement: 删除当前会话

当前会话删除成功或确认已不存在时，系统 MUST 在原 workspace 创建新的空 UUID 会话，清空旧消息区、输入草稿、本轮用量及工具授权。删除失败 MUST 保留当前会话；删除其他会话 MUST 保持当前状态。已删除目标 MUST 不再参与后续保存。

#### Scenario: 当前会话包含在批量目标中
- **WHEN** 当前会话与多条历史会话一同被成功删除
- **THEN** 系统只创建一个新的空会话，沿用原 workspace，旧会话不会被保存流程重新写入

### Requirement: 删除命令与确认

系统 MUST 提供 `/delete <id> [id...]` 和显式 `--yes` 参数。交互界面无 --yes 时 MUST 先确认并默认取消；非交互输入无 --yes 时 MUST 只提示用法，不读取后续输入作为确认。确认 MUST 显示目标数量与完整 UUID、保留 Trace 的说明，以及当前会话替换提示。

#### Scenario: 管道安全输入
- **WHEN** 管道依次输入不带 --yes 的删除命令和另一条命令
- **THEN** 删除不执行，后一条命令按原语义处理

#### Scenario: 显式批量删除
- **WHEN** 用户输入 `/delete --yes` 后跟多个完整 UUID
- **THEN** 系统删除精确指定的目标并逐项输出结果，不接受标题、前缀或通配符代替 UUID
