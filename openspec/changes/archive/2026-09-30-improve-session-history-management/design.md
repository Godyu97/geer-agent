# Design

## Context

动机见 proposal。现有 SessionManager 合并进程内状态与近期存档，GUI 已消费结构化列表，TUI 仅输出列表文本。Prompt 的事件队列会在保存后清空，模型历史会压缩，因此不能从当前模型上下文推导原始首句。SQL/MongoDB 都保存检查点与原始事件，Trace 独立存储。

## Goals / Non-Goals

保持消息归 Prompt 所有、会话归 SessionManager 所有、DAO 隐藏后端差异；将标题与删除报告作为界面投影。无数据库迁移、不新增 crate 或配置、不改工具调度与模型流式语义。

## Decisions

- 在 Prompt 内存保留首条输入（不加入 PromptSnapshot），加载时从已验证的事件链重建。共享标题函数负责规范化和字符截断。历史列表缓存记录事件头与标题；读取错误不永久缓存。比每次展开整个聊天记录更省读写，也不引入数据库命名字段。
- SessionEntry 和 SessionStatus 增加展示标题；Session trait 增加结构化列表、删除预览与批量删除接口。预览复制目标 ID，避免确认期间列表排序改变目标。删除报告使用 Serialize 枚举表达每项状态，避免前端解析自然语言。
- 删除按 ID 串行执行，内存状态在确认删除后才移除。当前会话最后处理，用 fresh 直接替换，丢弃旧状态而不 park/save。Agent 仅在当前 ID 变化时重置工具授权和本轮用量。
- SQL 使用每会话事务删除检查点及全部关联事件；MongoDB 先删除检查点再清理事件，并将清理异常作为 cleanup_pending 返回。比引入副本集事务或墓碑迁移更适合现有四后端契约。重复请求即使找不到检查点也清理事件，Trace 表不参与删除。
- GUI 继续通过 gui_submit 工作队列执行；命令结果新增 confirmation/report，确认后的 --yes 请求重新经过 busy/closing 检查。React 管理选择集合并以 UUID 对齐快照。TUI 增加列表/删除确认模式，分离聊天草稿与选择状态，用 Action 将异步会话操作交还运行循环，避免持有屏幕 RefCell 借用跨 await。
- 交互 REPL 检查输入输出是否终端，提示一次 y/N；管道必须 --yes。TUI/GUI 的 --yes 同样是显式删除，不再重复确认。工具授权不复用删除确认，避免一次授权扩大权限。
- 沿用 Rust 的所有权和 Result/枚举报告，std 集合保存选择和缓存；异步读写复用现有运行时；不新增依赖。教程会话管理映射为已有状态对象的增量方法，不复制日程目录。

## Risks / Trade-offs

- MongoDB 两次删除间可能失败 → 检查点确认删除后即移出可保存内存，单独报告残留事件并支持重试。
- 历史事件首次读取可能较多 → 进程内缓存，同一检查点只计算一次；沿用近期 20 条限制。
- 其他进程持有旧会话 → 保留 revision 更新约束，禁止失败更新改为插入；不新增跨进程推送同步。
- 同名标题和多字节文本 → 身份始终使用 UUID，截断按字符，不按字节；确认中显示完整 ID。

## Migration Plan

无需数据迁移，旧会话直接从已有事件生成标题。正常删除不可撤销，确认清楚说明 Trace 保留。交付前用隔离数据库和模拟服务验证，再执行默认/GUI 两组质量门；外部服务与 Windows 运行未验证时单列边界。
