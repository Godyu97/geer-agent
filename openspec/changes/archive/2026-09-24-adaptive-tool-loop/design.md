# Design

## Context

见 `proposal.md`。现有 `agent` 已按单次输入维护 Turn 与 Tool Call 预算，`Prompt` 可添加只对一次请求生效的指令；`tools` 同时拥有授权状态和执行逻辑，文件读取同步，Bash 为异步进程。两种流式接口目前没有把用量交给 `agent`。本变更沿用 Day 2 的 `tool-loop`，不改变模型调用和会话历史的所有权边界。

## Goals / Non-Goals

**Goals:** 在原循环里增加可验证的调度、停机判断、资源核算和结构化本地记录。每组任务落地后仍可运行 REPL。

**Non-Goals:** 不构造通用工作流引擎；不猜测兼容模型价格；不让未授权工具并发执行。

## Decisions

1. **工具调度与所有权。** `tools` 公开执行模式，只将 `read` 视为可并行；`get_current_time` 可独立执行但不参与“读取进展”。Bash、write、edit 和未知工具均串行。按调用顺序切分相邻只读段，先在主任务中逐项解析参数及确认授权，再把已授权的读取交给阻塞任务并行执行；只读段的结果按原顺序收集。这样 `Tools` 的可变授权状态不跨任务共享，写入不会与前后读取竞态。已有 `tokio` 和 `futures-util` 足够，不加 crate。相比把整批同时 `join_all`，顺序边界可直接保证有副作用工具的语义。
2. **结构化工具结果。** 工具内部返回正文、成功与否；最终仍把原正文交给模型。文件操作以其 `Result` 判断成功，Bash 以退出码判断失败，授权拒绝和无效参数也算错误。比从中文字符串猜错误可靠；用户看到的已有正文格式保持不变。每次实际调用的记录保留稳定的调用/结果摘要与耗时，绝不记录原文。
3. **循环与进展。** 对参数 JSON 归一化后与工具名求摘要，再加结果正文摘要；单次请求内连续三次完全相同记录提示、第四次终止。连续错误也是三次提示、第四次终止。每个含工具的 Turn 若没有新的调用及结果组合、成功修改或新读取片段，则无进展计数加一；三次提示、第四次终止。成功修改会清除无进展计数并打断连续重复；重复测试经过修改后允许继续。摘要仅用于本次进程，不要求跨运行稳定。相较完整“进展评分”，布尔证据更容易理解和测试，也避免把读到相同错误算成进展。
4. **用量、费用、配置与流式。** 在 `ModelStep` 加可选输入/输出 Token 用量。Responses 从完成事件取；Chat 请求流式用量并在正文结束后短暂等待末尾用量事件。累计用量来自接口报告，不用字符数冒充 Token。默认只有 10 分钟时长上限；Token 与费用上限用环境变量选择启用。费用上限必须同时提供输入/输出每百万 Token 的美元单价，否则配置失败；未知用量时有资源上限的请求停止继续工具并标明原因。费用用 `f64` 计算，配置拒绝非有限/负数；仅用于预算和展示，不用于结算。模型最终化可再请求一次，无工具；这是预算收敛的保留额度。
5. **动态软提示与指标。** 硬上限维持 30 Turn / 100 Tool Call；近期持续有进展时通用软提示从第 12 Turn 推迟至第 15 Turn，停滞时立即给改进提示。终止原因和完整指标由 `agent` 一次性打印为 stderr JSON 行，每次工具也记录单独 JSON 行，含运行 ID、Turn、工具名、摘要、成功和耗时。stdout 仍只用于 REPL 文本。当前只有一种 Agent，因此不凭输入文本推断 Simple/Coding/Research 类型；后续可显式选择预算配置。
6. **超时和错误处理。** 用异步截止时间限制常规模型请求；执行前及每批完成后检查时长。预算触发时进入原有无工具 Finalization，失败时沿用本地兜底。已执行的完整 call/result 对会提交；尚未执行的超额批次不写入历史。串流中途失败沿用原有回滚/提交语义。`provider` 不引用 `tools`，`tools` 不引用 `agent`。

## Risks / Trade-offs

- [兼容接口不提供用量] → 无上限时指标标记未知；配置 Token/费用上限时停止继续工具，避免虚假的预算保证。
- [Chat 的用量尾包迟到] → 有界等待，不让正文结束后的等待无限延长；缺失按上述规则处理。
- [进展启发式误判] → 先提示再终止，成功修改打断重复序列，硬上限仍兜底。
- [同步文件读取已被派发后超时] → 单次读取仍受现有字节/行数上限，收齐结果后检查时长并收敛。

## Migration Plan

无需数据迁移；新增资源上限配置均可选。旧的第一阶段预算行为保持默认，删除新配置即可回到仅 Turn/Tool Call/时长限制。先归档基线 `tool-loop` 与 `budgeted-tool-loop`，再归档本变更。
