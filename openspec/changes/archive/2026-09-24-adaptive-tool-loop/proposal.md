# Proposal

## Why

Day 2 的 `tool-loop` 已完成第一阶段预算循环，但同一 Turn 的工具仍串行执行，也无法识别重复失败和无进展调用。第二、三阶段需要在现有循环上补上安全调度、资源统计与收敛判断，使复杂任务能继续推进，同时及时停止空转。

## What Changes

- 同一 Assistant Turn 的独立只读工具可并行执行，结果仍按原调用顺序回传；命令和文件修改等可能改变状态的工具保持顺序执行，现有授权仍逐项生效。
- 连续工具错误、相同调用得到相同结果、连续无进展会先提示模型换方法；继续空转时关闭工具并请求最终回答。
- 对每次请求记录 Turn、实际工具调用、错误、进展、耗时、模型报告的 Token 用量、可计算的费用及结束原因；记录每次工具的耗时与成功状态，不记录参数和结果原文。
- 以可选环境配置启用 Token 和费用上限；费用按显式配置的模型单价计算，接口没有提供可靠用量时明确停止继续执行工具。执行总时长有默认上限。
- 软预算根据近期进展调整提示时机，硬 Turn 与 Tool Call 上限仍保持第一阶段的安全边界。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `tool-loop`：补充并行只读调度、循环及进展保护、资源预算和运行指标。

## Non-goals

- 不把 Bash 命令自动归类为只读；它仍需授权并顺序运行。
- 不根据模型名称猜测价格，也不上传遥测或构建统计服务。
- 不为尚不存在的 Subagent、Research Agent 引入框架或任务类型推断。
- 不改变第一阶段的工具协议、会话提交与回滚规则。

## Impact

增量修改 `agent`、`tools`、`provider`、`config` 及相关测试；使用已有依赖，不新增 crate。`tool-loop` 的主规格仍待此前已完成的变更归档，归档顺序需要保持基线在前。
