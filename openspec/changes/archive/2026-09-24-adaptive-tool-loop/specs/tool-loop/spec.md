# Spec Delta

## MODIFIED Requirements

### Requirement: 工具调用循环

系统 MUST 在两种已支持的模型接口中声明可用工具，收集完整调用后执行，并使用对应调用标识回传结果；每个 Assistant 响应 MUST 只计为一个 Agent Turn，每个实际执行的工具调用 MUST 独立计数，系统 MUST 继续循环直到模型产生最终回答或执行预算要求收敛。同一响应中的独立只读文件调用 MAY 并行执行，其他调用 MUST 保持原有顺序。

#### Scenario: 查询当前时间

- **WHEN** 模型请求当前时间工具
- **THEN** 系统返回真实本地时间，模型可依据结果继续回答

#### Scenario: 单个 Turn 包含多个调用

- **WHEN** 模型在一个 Assistant 响应中返回三个独立文件读取
- **THEN** 系统记录一个 Agent Turn 和三个 Tool Call，可并行执行这三个读取，按原调用顺序配对结果并继续向模型请求

#### Scenario: 连续调用超过旧上限

- **WHEN** 同一用户输入已完成五个包含工具调用的 Agent Turn、模型仍请求工具且各项预算仍有余量
- **THEN** 系统继续执行调用，而不是以旧的五轮限制终止任务

### Requirement: 工具执行预算与收敛

系统 MUST 对每次用户请求应用独立预算，默认软 Turn 上限为 12、硬 Turn 上限为 30、实际 Tool Call 上限为 100；软上限用于向模型提供收敛提示，近期持续有进展时可动态推迟通用提示但不突破硬上限。任一硬上限用于停止工具执行并在协议层关闭工具后请求最佳可用最终回答。最终回答 MUST 基于已有上下文，并明确任何未完成或未验证的工作。

#### Scenario: 达到软 Turn 上限

- **WHEN** 同一用户请求已经完成 12 个 Agent Turn 且尚未自然结束
- **THEN** 系统在近期没有持续进展时加入通用预算提示；有持续进展时可推迟该提示，仍保留硬预算约束

#### Scenario: Turn 预算接近耗尽

- **WHEN** 同一用户请求的剩余 Turn 不多于三个
- **THEN** 系统向模型说明准确的剩余 Turn，并随余量减少强化立即收敛的要求

#### Scenario: 硬 Turn 上限触发 Finalization

- **WHEN** 同一用户请求已经完成 29 个 Agent Turn 且仍未产生最终回答
- **THEN** 系统将第 30 个且最后一个允许的 Assistant 响应用于 Finalization，不声明或执行任何工具，并要求模型仅使用已有上下文回答

#### Scenario: Tool Call 批次超过剩余预算

- **WHEN** 执行当前 Assistant 响应中的完整工具批次会使实际 Tool Call 总数超过 100
- **THEN** 系统不执行该批次中的任何调用，停止提供工具，并在剩余 Turn 内进入 Finalization

#### Scenario: Tool Call 预算恰好耗尽

- **WHEN** 一个完整工具批次执行后实际 Tool Call 总数达到 100 且模型尚未给出最终回答
- **THEN** 系统不再发起可调用工具的模型请求，并在剩余 Turn 内进入 Finalization

#### Scenario: Finalization 无法产生有效文本

- **WHEN** 无工具的 Finalization 请求失败或仍返回工具调用而没有可用最终文本
- **THEN** 系统不执行该调用，保留已经完成的调用与结果，并向用户明确显示预算已耗尽及回答未完成

## ADDED Requirements

### Requirement: 安全的多工具调度

系统 MUST 允许同一模型响应返回多个工具调用，并在授权后并行执行相互独立的只读文件调用；可能修改状态或运行命令的调用 MUST 按模型给出的顺序执行。所有调用结果 MUST 按原调用顺序与标识回传，且工具授权规则 MUST 保持有效。

#### Scenario: 三个独立读取

- **WHEN** 一个响应请求读取三个不同文件，且用户已授权读取
- **THEN** 系统允许这些读取并行执行，并按请求顺序回传三个对应结果，只计一个 Agent Turn 和三个实际 Tool Call

#### Scenario: 读取与写入混合

- **WHEN** 一个响应按读取、写入、读取的顺序请求同一文件
- **THEN** 系统先完成第一次读取，再执行写入，最后读取修改后的文件，不让跨越写入的读取并行

### Requirement: 空转和错误保护

系统 MUST 区分工具成功与失败，并跟踪相同调用及相同结果的连续重复、连续工具错误和连续无进展 Turn；达到预警阈值时 MUST 向模型提供仅限本次请求的改进提示，继续达到终止阈值时 MUST 停止执行后续工具并尝试无工具的最终回答。不同结果或有效修改 MUST 重置相应的无进展判断。

#### Scenario: 重复无效搜索或读取

- **WHEN** 相同工具和参数连续返回相同结果，且模型在提示后仍重复
- **THEN** 系统不再继续相同调用，结束原因标为重复工具循环，并要求模型说明已完成与未完成的工作

#### Scenario: 测试失败后修改再测试

- **WHEN** 同一测试命令失败后有成功的文件修改，随后再次运行该命令
- **THEN** 系统视修改为可能进展，不因重复命令直接终止任务

#### Scenario: 连续错误

- **WHEN** 连续三个工具执行失败
- **THEN** 系统提示模型改用不同方式；若下一次仍失败，停止工具执行并要求最终回答

### Requirement: 资源预算与运行记录

系统 MUST 对每条用户请求限制总执行时长，并在已配置 Token 或费用上限时按模型实际报告的用量核算；模型无法提供可靠用量时 MUST 明确停止继续执行工具。系统 MUST 记录结束原因、Turn、工具调用与错误、Token、可计算费用、耗时和进展指标；工具记录 MUST 包含耗时与成功状态，但 MUST 不包含调用参数、结果原文或密钥。

#### Scenario: Token 或费用预算耗尽

- **WHEN** 已报告的累计用量达到配置上限，且模型仍请求工具
- **THEN** 系统不执行该工具批次，关闭工具并请求基于已有上下文的最终回答，记录对应结束原因

#### Scenario: 用量缺失

- **WHEN** 配置了 Token 或费用硬上限，而兼容接口未报告本轮用量
- **THEN** 系统明确记录用量不可用，停止进一步工具执行并尝试最终回答

#### Scenario: 时长耗尽

- **WHEN** 单次请求达到时长上限，且尚未自然完成
- **THEN** 系统停止继续执行工具和常规模型轮次，尝试无工具最终回答并记录超时原因

#### Scenario: 有进展的复杂任务

- **WHEN** 任务不断产生新的有效结果且尚未达到硬上限
- **THEN** 系统可推迟通用软预算提醒，但仍保持硬 Turn、Tool Call、时间、Token 与费用边界
