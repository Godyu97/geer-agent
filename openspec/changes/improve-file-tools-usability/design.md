# Design

## Context

动机和范围见 [proposal.md](proposal.md)。工具定义由 `agent::tool_specs` 转换为 provider 的中立定义，两种协议分别序列化；文件读取和修改集中在 `src/tools/file.rs`，授权和批调度集中在 `src/tools/mod.rs`。`src/tools/bash.rs` 已持有配置过的 Bash 路径、启动目录、10 秒超时、每路 8 KiB 输出捕获和完整结果 2000 字符限制。

现有问题是参数缺少用途和边界说明、读取定位信息不足、编辑错误缺少恢复建议，以及重叠匹配和无效修改反馈不准确。用户进一步要求增加正文正则搜索，并明确 `ls/glob/rg` 直接使用 Bash 执行现成命令，不自己实现文件遍历和匹配。

`file-tools` 原 change 已完成，但主 spec 清单只有 `tool-loop`。本次 delta 继续基于原 change 的四条要求补充和修改，未来合入主 spec 时需先建立原基线。

## Goals / Non-Goals

**Goals:** 为模型提供清楚的工具选择、参数和结果，用现成命令完成目录浏览、路径查找和正文搜索；保留已有文件读写、授权和 Agent 循环。

**Non-Goals:** 不自行实现目录遍历、通配匹配或正则引擎，不新增相关 crate，不复制现成命令的全部选项，不建立目录分页或快照系统；不引入插件、索引、网页抓取或新权限层。

## Decisions

### 1. 三个独立入口，复用同一 Bash 执行层

面向 LLM 保留 `ls/glob/rg` 三个工具。它们分别回答“目录下有什么”“哪些路径符合命名模式”“哪些文件内容符合表达式”。若合成一个带 `mode` 的工具，模型仍要选择模式，并额外处理不同模式的必填参数、输出和 `pattern` 含义；本项目工具规模较小，保持单一职责更容易写清契约。这是设计判断，真实调用准确性仍需抽样验证。

底层直接映射到现成命令：

| 模型工具 | Bash 执行的命令形态 | 用途 |
| --- | --- | --- |
| `ls` | 在目标目录执行 `ls -1Ap` | 单列列出直接子项，含隐藏项，用目录后缀辅助辨识 |
| `glob` | 在搜索根执行 `rg --files --glob PATTERN` | 按路径通配模式列出文件 |
| `rg`，`output=content` | `rg --line-number --with-filename --no-heading -e PATTERN` | 正文匹配，提供路径、行号和命中行 |
| `rg`，`output=files` | `rg --files-with-matches -e PATTERN` | 只列正文命中的文件 |

以上是命令形态，不是将参数插入 Shell 字符串的模板。`glob` 不需要单独的 glob 命令，也不使用 Bash 的隐式通配展开；模式原样交给 ripgrep。`rg.glob` 作为 `--glob` 传入，只负责过滤路径；正文 `pattern` 作为 `-e` 参数。按字面文本搜索时加 `--fixed-strings`。不额外编写 Rust 的遍历、匹配、排序或 ignore 解析器。

原 `read/write/edit` 仍保留 Rust 标准库实现及本次增强；“通过 Bash 执行”的要求只应用于新增的目录与搜索工具，不改写已运行的精确编辑路径。

### 2. 最小参数与清楚的选择指引

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `ls` | `path?` | 目录路径，默认启动目录；截断后缩小目录范围，不提供自定义 offset/limit |
| `glob` | `pattern`, `path?` | 路径通配模式；搜索根默认启动目录；不搜索正文 |
| `rg` | `pattern`, `path?`, `glob?`, `output?`, `fixed_strings?` | 搜索文件或目录中的正文；默认根为启动目录，`output=content`，`fixed_strings=false` |
| `read` | `path`, `offset?`, `limit?` | UTF-8 原文；偏移按行从 1 开始；默认 1、2000，超过 2000 仍按 2000 截取 |
| `write` | `path`, `content` | 新建或整体覆盖；内容必须完整 |
| `edit` | `path`, `edits[{oldText,newText}]` | 局部精确替换；每个旧文本在修改前原文中唯一且各项不重叠 |

每个工具使用短 description、完整字段说明和一个最小例子。`output` 只允许 `content/files`；非空模式可以包含空白，不能因 trim 改变搜索含义；路径不能为空白。正文正则与路径 glob 分别说明，不把 `files` 输出解释为按正则搜索文件名。不增加任意 `args` 或 `command` 参数。

参数类型、必填项、未知字段和枚举值在授权前检查，嵌套编辑项同样校验；模式语法直接由底层命令校验，其错误原样作为诊断返回。可选字段省略时使用默认值，显式 null 仍报错。`read.limit` 保留既有截取兼容性，不新增与之冲突的 schema 最大值。

`bash` 描述补充专用文件工具的选择指引。跨工具指引由 `src/prompt/mod.rs` 统一持有：根据已知线索直接选目录、路径或正文搜索，不强制每次依次调用三个工具；搜索命中后用 `read` 获取完整原文再编辑。拒绝授权后不改用其他工具绕过拒绝。provider 不承载这些规则，也不为本次更换 strict 模式。

### 3. 对现有 Bash 执行器做必要的小幅复用

将 `src/tools/bash.rs` 中“启动进程、捕获 stdout/stderr、超时和退出码”抽成内部结果，已有 `bash` 继续使用原格式输出，保持既有接口和测试行为。新查询工具使用同一执行核心，并能读取真实退出码与截断标记；不能从“退出状态：...”的展示文本倒推状态。

新增入口传入固定脚本和独立参数：通过 `bash -c <固定脚本> <固定的占位名> <参数...>` 让脚本读取 `$1`、`$2` 等位置参数，在脚本中始终双引号引用。路径使用已有 `resolve_path` 处理相对路径、绝对路径和家目录简写；执行命令使用 `--` 终止选项，正文模式通过 `-e` 传入。用户提供的引号、反引号、命令替换符号或前导短横线都不能变成 Shell 代码或额外选项。

`ls/glob` 固定脚本先切换到已解析的目录，失败即以专用退出码结束（例如 125），避免与 ripgrep 的无匹配退出码 1 混淆，再 `exec` 对应命令；`rg` 搜索文件或目录时在已知启动目录下传入解析后的路径。最终命令使用 `exec`，使既有超时机制直接控制查询进程。仍移除已有执行器屏蔽的敏感环境项、关闭 stdin，并有界捕获两路输出。

统一采用现有 10 秒超时、每路 8 KiB 捕获和完整结果 2000 字符限制；新工具不再承诺 200 项/50 KiB 的自定义列表或分页。元信息、诊断和截断提示都计入完整结果预算。保留底层输出，不为搜索结果增加复杂解析器；输出截断时明确提示缩小 `path/pattern/glob`，不返回虚构的总数或续页游标。查询返回片段只用于定位，精确编辑仍先通过 `read` 获取原文。

新工具显示 `exit_code`，并单独计算语义上的成功：`rg/glob` 的正常退出 1 表示无匹配，可作为成功的空结果；退出 2、无法启动、命令不可用和超时按错误反馈，已有通用 Bash 仍按原来的退出码规则判断成功。非空 stderr 保持可见，部分结果伴随错误时不能报告查询完整。

### 4. 使用现成命令的过滤规则和部署依赖

ripgrep 调用加 `--no-config` 防止 `RIPGREP_CONFIG_PATH` 隐式注入选项，加 `--color never` 保持结果适合模型读取，以 `--sort path` 提供稳定路径次序；目录列表采用固定 locale。忽略文件、隐藏路径、二进制判定、显式搜索路径和 `--glob` 的优先级均沿用 [ripgrep 官方指南](https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md)。尤其不能承诺显式 `--glob` 仍无条件遵守所有 ignore 规则，其覆盖语义需要写入参数说明。

不再自定义 `target/node_modules` 剪枝表，不自己解析 `.gitignore`，也不强行将目录列表与递归内容搜索的过滤规则变成一样；工具说明解释 `ls` 展示隐藏项，而递归搜索受原生命令规则影响。正则采用 ripgrep 默认引擎，本轮不开放多行或 PCRE2 切换；不支持的表达式返回命令诊断，可建议简化表达式或改用字面匹配。

本次不新增 Cargo 依赖。`ls` 和 `rg` 从已配置 Bash 的 PATH 查找；缺失或不支持必要选项时，仅对应工具返回 `tool_unavailable` 或命令失败，其他聊天与文件读写继续可用。不自动安装、不硬编码当前机器上的可执行文件路径，也不借机新增依赖管理或配置体系。列表的引用和特殊文件名表示沿用底层命令，结果元信息始终说明搜索根与路径解释基准，不承诺通用的机器可解析文件名列表。

### 5. 保持原文读取、精确编辑和可恢复结果

文件工具结果继续是字符串，首行使用紧凑 JSON 元信息，空行后是原始正文、命令 stdout 或诊断。`read` 的正文不加行号、围栏或人为省略号；元信息包含路径、实际行范围、截断状态和 `next_offset`，不统计整个文件总行数。空文件行范围为 null、正文为空；读到 EOF 时不再提供续读偏移。仍按完整行与 UTF-8 边界限制正文，总结果不超过 50 KiB，元信息也计入预算。

`ls/glob/rg` 只提供查询元信息、根路径、退出状态、截断标记和有界命令输出；不重复回显无界模式，不把截断行当作完整原文。未命中明确显示为空结果；命令错误保留有界 stderr 及修正建议。参数、授权、文件操作错误仍给出稳定类别和具体下一步，工具自己不额外加入时间戳或耗时，保持结果指纹有意义。

`edit` 保留“读取 → 在同一份原内容定位全部编辑 → 检查区间互斥 → 构造结果 → 写盘”的流程。唯一性比较第一个和最后一个匹配位置，补上 `aaa` 中 `aa` 的重叠歧义；依据是 [Rust 字符串匹配文档](https://doc.rust-lang.org/std/primitive.str.html#method.match_indices) 明确其匹配迭代器不返回重叠匹配。缺失、歧义、区间冲突分别建议重新读取、扩大旧文本上下文或合并编辑，并保证校验失败不写盘。

通过私有文件结果把实际 `changed` 传给已有 `ToolOutput`。`write` 比较已有字节，只有不存在才走新建，其余读取失败直接报错；相同内容不写盘，创建空文件算改变。`edit` 在换行还原前发现最终规范化内容未变化时直接返回，继续保留 BOM 和统一 CRLF/LF 策略。现有 `LoopGuard` 无需改算法，只需接收到真实的 `changed=false`。

### 6. 工具注册、授权和异步边界

使用小型固定工具列表和内部 `ToolKind` 统一工具定义、名称解析和执行模式，初始化检查重复名称，不引入动态插件表。泛化只读准备结果，支持 `ls/glob/rg/read`：本地 `read` 持有已解析参数和路径并继续通过 `spawn_blocking` 执行，三个命令查询持有固定命令种类和拥有所有权的参数，使用已有异步 Bash 进程核心；不会把确认回调或 `&mut Tools` 移入工作线程。

主线程逐项校验并授权，连续只读段可在 `join_all` 中并行，结果按调用顺序回传。写入、编辑和通用 Bash 继续作为顺序边界；只有固定模板的专用查询标记为只读，不按任意 Bash 命令文本猜测是否只读。

授权仍按模型可见的工具名独立保存：允许 `rg` 只意味着允许该固定搜索操作，不授予任意 Bash；查询直接调用内部执行核心，不再次经过模型可见 `bash` 工具造成双重确认，也不绕过专用工具自身授权。`GEER_AGENT_TOOLS` 和 `/reset` 行为不变；provider、Prompt 历史及流式输出沿现有边界运行。

### 7. 验证正确性与模型效果

命令适配验证实际调用参数、带空格和引号的路径、字面传递模式、内容/文件输出、无匹配、非法正则、命令缺失、权限错误、超时和输出截断。可用假命令进程固定退出码和输出，也在当前可用的 `ls/rg` 上用隔离临时目录做真实命令冒烟；这只验证封装，不为成熟命令重写正则或遍历算法测试。

原文件操作继续覆盖完整行续读、UTF-8/CRLF/BOM、编辑歧义和原文基准、失败不落盘、无效修改与 Agent 计数。调度验证混合只读查询、写入屏障、逐工具授权、拒绝、关闭和重置；通用 Bash 的原结果格式与判错语义保留回归。

两种协议的 HTTP mock 验证六个文件工具（加时间与 Bash 共八个）的定义、参数说明、结果与调用标识配对、关闭工具和 Finalization 后恢复；不为测试放宽生产授权。真实模型抽样检查能否根据目录名、路径模式和正文内容分别选对工具、搜索后读取精确原文，并按错误建议修正。离线检查与真实模型效果分开报告，不能仅凭 mock 宣称准确率已经提升。

## Risks / Trade-offs

- [依赖本机命令及其版本] → 复用用户已选择的 Bash 环境，命令缺失或选项不支持明确失败；本机命令验证不等同于 Windows 或其他主机验证。
- [合并执行代码影响原 Bash 行为] → 原入口保留原参数、输出格式、超时与退出码语义，新查询只复用内部执行核心并单独解释搜索退出码。
- [命令输出不是目录快照，且可能截断或包含特殊文件名] → 明确根目录与截断状态，保留原生命令表示，不承诺无遗漏的分页或通过展示文本无损重建所有路径。
- [新增定义增加请求长度] → 每个工具只放一个短例子，公共指引不重复参数文档，并记录序列化大小；不声称工具数量或请求体积必然下降。
- [并发文件修改或混合换行] → 保留已有行为边界，不引入跨进程锁或原子回滚；验证统一 CRLF/LF 和无效编辑不改盘。
- [主 spec 尚无 `file-tools`] → 当前 delta 校验只证明结构完整，未来须先同步原 `file-tools` 基线再合入本次增量。

## Migration Plan

先复用 Bash 内部执行结果并保持原入口行为，再新增三个固定查询封装、增强原有文件读写，最后补齐调度与模型定义回归。无新增 crate、配置或数据迁移；所有规划任务完成前不改动历史会话。若回退实现，一并回退新增工具定义、指引和结果变化。主 spec 同步或归档仍留给后续明确请求。
