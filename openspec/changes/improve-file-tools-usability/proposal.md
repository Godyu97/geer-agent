# Proposal

## Why

当前 `read/write/edit` 已能完成文件操作，但模型看到的参数缺少用途、单位和边界说明，查找文件还需要自行组织 Shell 命令，读取结果和编辑错误也不足以指导下一次调用。本变更参考 [GeekAgent Day 4 文件工具与注册表](https://geektutu.com/post/geekagent-day4.html)，沿用 `file-tools` 能力，完善“按目录、路径或正文定位文件 → 有界读取 → 精确修改 → 验证”的可运行切片。

## What Changes

- 新增三个独立工具入口：`ls` 查看目录、`glob` 按路径通配模式找文件、`rg` 按文件正文正则匹配；搜索可选择返回匹配内容及行号，或仅返回命中文件路径。
- 文件发现与搜索沿用现成命令的行为，返回有界结果、退出状态和截断提示；缺少命令、模式无效、执行失败与正常无匹配明确区分。
- 为六个文件工具补齐选择场景、参数说明、默认值、范围和简短示例；明确局部修改优先 `edit`、新建或整体替换使用 `write`，纯文件查看优先专用工具。
- `read` 返回可辨识的路径、实际行范围、截断状态和可直接使用的续读参数，正文保持原文，便于复制为编辑锚点；保留从 1 开始的行号和现有读取上限。
- 文件操作失败时给出原因和具体恢复建议；编辑缺失、重复（含相互重叠的重复匹配）或区间冲突均不落盘，同一批编辑仍基于原文件检查。
- 写入或编辑内容没有实际变化时明确返回“未改变”，避免把无效修改计入 Agent 的有效进展。
- 新增工具接入现有会话授权、总开关和只读并行调度；两种模型接口获得同一套定义和结果语义。

## Capabilities

### New Capabilities

无新增能力 id。

### Modified Capabilities

- `file-tools`：补齐目录、路径和本地正文匹配三种文件定位方式，以及模型可理解的调用契约、读取定位信息、可恢复错误和实际变更反馈。该能力已在 `openspec/changes/file-tools` 实现，尚未形成主 spec；本变更沿用原 id，并以其完整 delta 为基线。未来同步或归档须先建立原 `file-tools` 基线，再合入本次增量，不在本轮归档旧 change。

## Non-goals

- 不将 `edit` 改名为教程的 `patch`，不更换 `oldText/newText` 字段，不引入模糊匹配、正则编辑或按行号修改。
- 不调整现有按工具首次授权、任意路径访问与 `/reset` 撤销的权限模型；不引入逐次 diff 确认、回滚或仓库隔离。
- 不自行实现目录遍历、通配符匹配或正则搜索，不新增对应 crate；不做全文索引、网页抓取、图片读取、插件系统、通用 JSON Schema 校验框架或新的运行预算机制。
- 不改变模型接口、流式协议、会话存储或 trace 功能。

## Impact

`ls/glob/rg` 作为薄封装复用 `src/tools/bash.rs` 的 Bash 执行能力，分别调用 `ls`、`rg --files --glob` 和 `rg`，不新增 Cargo 依赖。`src/tools/mod.rs` 负责定义、参数和授权，`src/tools/file.rs` 保留现有读取与修改逻辑，跨工具指引由 `src/prompt/mod.rs` 统一持有；provider 继续只适配协议。运行环境需在所配置 Bash 的 PATH 中提供 `ls` 和 `rg`，缺失时仅对应工具失败可见。相应调整工具单元测试、Agent 进展回归和两种接口的 mock 验证，保持现有工具的合法参数及授权方式。
