# 29 链表系列：按阶段理解所有权设计

[返回总目录](../README.md) · [上一篇](04-practices-and-ecosystem.md) · [下一篇](06-compiler-and-pitfalls.md)

对应原教程：“手把手带你实现链表”的所有阶段。以下为分阶段学习笔记；Unsafe 阶段讲设计与验收，不在本仓库实现底层容器。

## 先问到底需不需要链表

链表适合练习递归类型、指针、借用与迭代器，但不是初学项目的默认集合。已知节点时的局部插入可以很快，可查找位置、节点分配、缓存局部性都有成本。普通列表先考虑 Vec，双端队列先考虑 VecDeque。

geer-agent 的历史消息和工具结果用 Vec，循环观察用集合；本项目没有自定义链表。学习本章不意味着应把这些现有集合替换掉。

## 第一阶段：单向栈

数据布局首先需要解决递归类型的大小：节点里的 next 使用 `Option<Box<Node<T>>>`，Box 提供固定大小的间接指针。

```mermaid
flowchart LR
    A[head] --> B[节点 A：值与 next]
    B --> C[节点 B：值与 next]
    C --> D[None]
```

基本操作按所有权交接理解：push 取出旧 head，让新节点拥有它；pop 取出 head，把 next 重新交给列表，再返回旧节点的值。不要直接从 `&mut self` 背后搬走字段而不给替代状态。

```rust
struct Node<T> { value: T, next: Option<Box<Node<T>>> }

fn main() {
    let mut head = Some(Box::new(Node { value: 10, next: None }));
    let value = head.take().map(|node| {
        head = node.next;
        node.value
    });
    assert_eq!(value, Some(10));
    assert!(head.is_none());
}
```

这里仅演示一次 pop 的所有权，不是完整链表实现。完整实现还要测试空表、单节点、多节点，以及释放长链时递归析构可能造成的栈深度问题；可通过循环拆节点实现迭代释放。

## 第二阶段：泛型与三类迭代器

| 子节 | 理解重点 |
| --- | --- |
| 优化类型定义 | 用 Option 表示空链接，用泛型复用元素类型 |
| Peek | `&self` 只读借用，`&mut self` 可返回可变借用；不消耗节点 |
| IntoIter | 消耗列表，逐个交出 T |
| Iter | 借用列表，逐个交出 `&T` |
| IterMut | 独占借用，逐个交出互不重叠的 `&mut T` |

IterMut 难的不是写个循环，而是确保之前返回的可变引用仍活着时，下次调用不会再次返回同一元素。观察迭代器如何推进内部链接，联系 `Option::take`。

## 第三阶段：持久化单向链表

“持久化”在这里指保留多个结构版本，并共享未变化的节点；不是保存到磁盘。Rc 支持单线程共享尾部，Arc 可用于合适的跨线程场景。

布局和基本操作要确保创建新头不修改旧版本。Drop/Arc 小节则关注只在唯一拥有节点时继续拆链，共享节点不能被某个版本提前销毁。代价包括引用计数和间接访问，而不是“免费共享”。

## 第四阶段：双端队列与内部可变性

两端插入删除意味着要同时维护前后链接。Rc<RefCell<_>> 容易表达共享与修改，但必须处理强引用环、运行时借用与守卫存活。

Peek 的难点是不能返回一个依赖已销毁临时 Ref 守卫的裸 `&T`；对称操作要验证头尾同时更新；迭代器更要保持运行时借用有效。最终代码应通过空、单、多节点、交替两端操作验证不变量，而非只验证一个 happy path。

## 第五阶段：Unsafe 单向队列

| 子节 | 为什么需要它 |
| --- | --- |
| 数据布局、基本操作 | 用尾指针提高尾部操作便利性，同时确定节点真正的所有者 |
| Miri | 检测执行到的未定义行为 |
| 栈借用、测试栈借用 | 理解别名使用为何会使看似正常的指针操作无效 |
| 数据布局 2 | 修正表示方式，使移动、链接、释放的约束一致 |
| 额外操作、最终代码 | 给迭代、读取等能力补齐相同安全要求 |

裸指针复制不会自动转移节点所有权；每个分配必须有明确且唯一的回收责任。栈借用是帮助检查别名规则的模型，不能把历史文章中的模型细节当作 Rust 永远不变的完整内存规范。

## 第六阶段：生产级双向队列

| 子节组 | 阅读时逐项检查 |
| --- | --- |
| 布局、型变/PhantomData、基础结构 | 类型如何表达拥有关系和生命周期；是否误导自动 trait 推导 |
| panic 与安全 | 中途发生 panic 后，长度和链接是否仍可安全清理 |
| 组合操作、其他 trait | append、split、迭代、克隆等有没有沿用一致的不变量 |
| 测试、Send/Sync 与编译测试 | 不只测值，还测不能被允许的类型使用方式 |
| 游标实现、游标测试 | 光标位置与借用如何限制插入/删除；空表和边界位置如何定义 |
| 最终代码 | 回头对照每个 unsafe 操作的安全前提，而非只复制结果 |

`PhantomData` 不存储真实的 T，但会让编译器考虑某种类型关联。它不能用来“凭空证明安全”，其参数形态也影响方差和自动 trait。

## 最后两节：双单向与栈上链表

双单向链表通过改变链接和访问策略探索不同权衡；栈上链表把分配责任与借用期放得更显眼。先画出谁拥有节点、谁只是观察，再判断接口是否允许移动或销毁仍被引用的节点。

建议学到泛型栈与迭代器就回到 Agent 项目练习。需要写基础容器时再深入后半段，并使用其上游完整教材和官方工具文档。
