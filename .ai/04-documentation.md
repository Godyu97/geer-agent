# 文档维护与生命周期

## 唯一来源与更新职责

| 内容 | 维护位置与触发 |
| --- | --- |
| 所有任务必要的硬规则 | 根 AGENTS.md；独特局部约束只在确需时用局部 AGENTS.md，不新增其他客户端配置。 |
| 检索、组件/命令、工程边界、任务流程 | `.ai/00` 至 `03`；只随对应事实变化更新，命令回到 Makefile/清单核对。 |
| 模块、代码、测试和范围 | [catalog.json](catalog.json)；新模块、入口、测试归属或路径变化时更新。 |
| 人类可读模块路由 | [模块索引](../docs/mod/00-index.md)；与 catalog 同步增删和入口。 |
| 职责 / 当前实现 / 当前事项 | 模块 00 / 01 / 02；分别维护阅读路由、已实施流程与失败边界、真实未关闭缺口。 |
| 目标行为与历史决定 | 相关 OpenSpec change 或原有设计/计划；不复制整份协议进模块正文，不将未实施目标写成现状。 |

改动事实的人同步唯一来源，评审核对事实和验证证据；没有明确负责人时不虚构。catalog 与索引均为人工维护，不是生成器的不可编辑输出；修改二者后运行下方检查，普通任务不重新 bootstrap、不全仓追加流水或刷新日期。

## 覆盖范围与排除

catalog 的 `source_roots` 覆盖 Rust 源码与构建脚本、共用前端、根清单/锁文件/Makefile/配置样例、scripts、全部 tests、已安装 `.agents` 工作流和 OpenSpec 配置。检查目录中所有常规文件，包含 Shell、Python、JSON、HTML、CSS、图标及无后缀文件；代码按最具体路径唯一归属，测试入口可以共享。

`src/ui/frontend/node_modules` 是 Bun 安装的第三方依赖，`src/ui/frontend/dist` 是 Vite 生成的 GUI/Web 产物，显式排除并记录原因。它们在未安装/未构建的 checkout 中可以不存在，不能因此要求安装依赖才能查治理。新增排除先确认真实角色；第一方文件不能凭目录名或后缀跳过。

声明范围之外的根 `target`、运行时 `.env`/`.db`/会话与 Trace、教学 doc、设计 docs、OpenSpec 正文/历史分别属于构建/用户数据或已有事实文档，不作为业务源码归属扫描。`.ai`、`docs/mod` 和 AGENTS.md 是治理产物，由框架结构/链接检查另行核对。范围外不等于已检查；新发现应用或工程目录时先补 catalog，不能靠现有 complete 状态推断全仓无遗漏。

## 生命周期与事项

稳定事实随实现维护，不按日期自动过期。02 只登记影响模块的真实未关闭事项或有用决定，写明状态、证据/待核实原因和下一步；未运行业务检查在 01/交付说明报告，不为每个模块制造一条假 Bug。

`docs/design`、`doc/plan` 与 OpenSpec 验收记录保留历史语境；旧端口、旧 Make 别名、旧通过结果只能作当时证据。文档整理不改变实施状态，不把 tasks 勾完、到期或归档当成验收。纯治理接入不自动同步、归档或清理 OpenSpec；需要时按用户指定流程处理。

只有明确包含清理/归档的任务才执行整理：先预览，保留可追溯原文，迁移详情后保留未关闭摘要和链接。没有固定到期天数，不自动清理用户数据或未知附件。

## 检查与交付

从仓库根目录运行，需要 Python 3.9+ 标准库，无需全局 skill、Git CLI、Bun、网络或模型/数据库凭据：

```bash
python3 .ai/scripts/check_governance.py --repo . --framework
git diff --check
```

[仓库内检查器](scripts/check_governance.py) 沿用本轮全局 repo-ai-governance 的只读检查能力，项目适配允许尚未生成的排除路径，仍校验路径不越界。它不执行 catalog/文档命令、不加载全局 skill；缺 Python 时报告未运行并人工完成同范围核对，不自动安装运行时。

读取 `errors`、`warnings`、`limitations` 与 `source_coverage`：退出 0 只说明支持范围机械通过；覆盖还须 `status=complete`，且未归属、歧义和未检查链接为 0。退出 1 为结构/映射/链接问题，2 为调用问题。排除示例、空范围、读取失败和符号链接不能藏在通过结果后面。

检查器核对入口→总纲→模块导航、真实路径/类型、三件套、常见本地 Markdown 链接、模板槽位与声明范围内归属；它不检查锚点、规则一致性、命令可执行性、业务语义或客户端实际加载。额外相关 Markdown 用 `--files 路径...` 定向查，不扫描全部历史。新文件还要单独审查差异和空白，因为普通 `git diff --check` 不检查未跟踪文件。

交付分别报告治理机械检查、业务验证和 Agent 加载；新会话客户端自动加载需要单独实测，不能由当前会话收到指令或文件/链接齐备推断。geer-agent 的根指令读取实现见 [Prompt 模块](../docs/mod/prompt/01-implementation.md)，链接正文不自动加载；静态核对不能充当行为测试结果。
