# AI 上下文入口

目标是先定位，再按信息缺口加载。AGENTS.md 保存常驻约束；本文件是路由，不是全文预读清单。

| 信息缺口 | 去哪里 | 停止条件 |
|---|---|---|
| 已知文件或函数 | 目标代码、相邻调用与测试 | 能说明影响面及兼容行为 |
| 不知道模块归属 | [模块索引](../docs/mod/00-index.md)，再读模块 00 | 找到职责、代码与验证入口 |
| 技术栈、应用组成、启动或测试命令 | [项目与环境](01-project.md) 对应章节 | 确认工作目录、依赖和副作用 |
| 构建编排、测试隔离或进程夹具 | [开发工具模块](../docs/mod/dev-tooling/00-overview.md)，再按安全政策核对实际入口 | 找到服务限额、拒绝条件和整组回收边界 |
| 架构、契约、生成代码、跨模块访问 | [工程边界](02-engineering.md)，目标模块 01 | 明确本任务涉及的边界 |
| 实现、状态、错误分支 | 模块 01 的命中章节与源代码 | 明确当前行为和验证条件 |
| 新能力、Bug、验收或中断恢复 | [工作流](03-workflow.md) 对应章节 | 确定任务路线和完成证据 |
| 相关未关闭事项 | 目标模块 02 | 找到影响本任务的缺口；不读无关历史 |
| 文档变化或治理检查 | [维护与生命周期](04-documentation.md) | 明确更新来源和检查范围 |

读取顺序是路径 / 标题、摘要、命中章节、必要调用链；已知位置可直接进入事实。模块三件套齐备不代表必须一起加载。历史和完整变更目录默认不读。

当前实现由代码与测试核对，已接受契约以协议 / 规范确认，目标行为留在需求或变更记录；冲突按事实类型查来源。掌握目标、影响面、兼容边界和验证方式即可实施。输出截断时缩小检索，不用全文加载补救。

OpenSpec 主 spec 尚未覆盖全部已实施能力：有关联 change 时按 [规范状态路由](03-workflow.md#openspec-路由) 对照实施证据，不预读整个 changes 或历史。Git 同步口令直接按 [Git 路由](03-workflow.md#git-工作流) 读取对应 skill，仅加载所需 Git 元数据。
